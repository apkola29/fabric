# Review of the instruction layer: findings, checks and outcomes

The instruction layer is the text that tells an agent what it has, where its knowledge comes from, how sign-in works, what to do when a server does not answer, and how to look for newer skills and servers: `AGENTS.md` with the two files that import it (`CLAUDE.md` and `GEMINI.md`), the preamble that every profile loads, the `factory-router` skill and the new `factory-standards` skill. It was written after the owner asked that "the instructions should be set and sorted" for whichever agent runs, with every Fabric and Azure server and skill listed, sign-in before use, the open servers and the skills as the fallback, the existing deployments and the architecture, Well-Architected, security and cloud frameworks as knowledge, and a look for newer skills and servers on every run. Three model families then read it cold, each at a different slice, and the author checked every finding against the text, the code or the primary source before accepting anything. The replies are kept as the reviewers wrote them, with the agent's own header removed.

## What the author added to the review

1. **The first full run of the suite**, started while the fixes were being made, found one defect that no reviewer saw: the new test of the shims held the import line inside a string, and the validator of this repository read the escape letter in front of the import as the start of an e-mail address and failed 24 of its tests. The import is built from two strings now, and so are the mutation specifications.
2. **The mutation proof of the layer.** The specification `verification/tools/mutation_specs_instruction_layer.py` holds 58 mutations: 42 of the instruction files and the fact list (run against the 26 tests of the layer), 11 of the reference pack (9 tests) and 5 of the update summary (22 tests). The first run let four survive and one report an error. Two were gaps in the tests (the test that the skill explains each tag took any mention of the tag, and a note about a dropped contract could not be told from a note about a package, because the two cases never meet in the command, so a unit test of the report was added); one was a mutation that removed a link that a page of its own already watches (it now removes one that nothing else watches); and one had an anchor that occurs twice. All 58 are killed.
3. **The standards pack** was drafted and verified separately (see [standards-pack-findings.md](standards-pack-findings.md)).
4. **The instruction files stay small.** A test holds each of them to a budget of lines (`AGENTS.md` 100, the preamble 80, the router 110, the standards skill 80, each shim 3), so that what is always in context stays short.

## What was not proved

- No host was run against a model with these files. That the text of `AGENTS.md` reaches Copilot CLI once or twice, that Claude Code 2.1.162 takes it through the import, and that Gemini CLI and VS Code read the files as their pages say are all UNVERIFIED. The listing of the instruction files by Copilot CLI (version 1.0.102) is the one thing that was run.
- That an agent follows the text is not proved either. The tests prove that the files are consistent with the manifest, the commands and each other, not that a model obeys them.
- The agent plane has no network and no credentials, so what an unattended job can do with the hosted servers is the Phase 0 spikes (S2, S6) and not these files.
- The look for newer skills and servers has no runner for a job yet: the preamble tells a job to use the result that its runner gives, and the runner is not built. Today only a person's session runs the check.
