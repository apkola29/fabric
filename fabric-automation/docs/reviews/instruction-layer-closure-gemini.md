### C2-1. Medium. `factory-standards/SKILL.md` omits what `Note:` lines mean, how to handle conflicts between checks and an existing deployment, that checks are not a blocking gate, and whether a `[flag]` request stops the whole change

- **Where:** `toolchain/skills/factory-standards/SKILL.md`, lines 16 to 28 and 46 to 51.
- **What is wrong:** Four gaps in `toolchain/skills/factory-standards/SKILL.md` cause an agent to misuse the 87 checks and 10 notes in `references/*.md` (Scenario S11):
  1. **Unexplained `Note:` paragraphs:** The four reference files contain 10 `Note:` lines (validated by `StandardsPackTests.NOTE` in `scripts/test_toolchain.py`, line 7941) where official Microsoft pages contradict each other (e.g., `references/security-and-governance.md`, line 31; `references/architecture-patterns.md`, lines 28, 30, 32). `toolchain/skills/factory-standards/SKILL.md` never mentions `Note:` lines in section 2 (`"How to read a check"`, lines 20 to 28), leaving the agent with no rule that a `Note:` records an unresolved tension in upstream docs where either choice is acceptable if consistent with the deployment.
  2. **Conflict between a check and the existing deployment:** Section 1.1 (`SKILL.md`, lines 16) says to follow the existing deployment's pattern, while section 1.2 (lines 17) says to evaluate every applicable check as `"met, not met or not applicable"`. Nothing says that the existing deployment outranks `factory-standards` (source 1 vs. source 3 in `AGENTS.md`, lines 27 to 29) and that when the existing deployment intentionally follows a different pattern, the check is reported with that context rather than overriding the existing deployment or failing the review.
  3. **Checks vs. blocking gates:** Section 2 (`SKILL.md`, lines 24) defines `[gate]` and section 1.2 (lines 17) requires grading every check `"met, not met or not applicable"`, but `SKILL.md` never states that `factory-standards` checks inform the draft/review and are not a hard pass/fail gate.
  4. **Partial execution of a `[flag]` (T3) request:** On `"add a lakehouse with row-level security for HR data"`, `SKILL.md`, lines 26 and 50 (`"The factory does not make such a change in this version ... Flag it to a person with the id and the source"`, `"Do not turn a [flag] into a change"`) allows an agent to implement the lakehouse without RLS and merely flag `std-sec-08`, shipping an unprotected HR lakehouse instead of refusing/escalating a request whose security requirement (`[flag]`) is integral to the item.


### C2-2. Medium. Existing-deployment citation and preamble leak rules still allow workspace/item GUIDs from target Git backups to be copied or quoted into PRs and repo files

- **Where:** `AGENTS.md`, lines 10 and 27; `toolchain/instructions/factory-preamble.md`, lines 9 and 23.
- **What is wrong:** First, in `toolchain/instructions/factory-preamble.md`, line 9 (`"Never write a tenant, workspace, item or capacity identifier, a person's name or a local path into a file that this repository publishes"`), the prohibition covers only `"a file that this repository publishes"`—omitting pull request text (`AGENTS.md`, line 10 includes `"or into pull request text of it"`, but a job only reads the preamble). Second, in both `AGENTS.md`, line 27 and `toolchain/instructions/factory-preamble.md`, line 23, source 1 (`"The requirement, and what already exists"`) tells the agent to read the workspace Git backup, `"follow their names, layers and patterns, and cite the files you used"`, and only forbids copying or quoting `"a secret (a key, a token, a password, a connection string with one)"`. If an existing item definition, script, or pipeline in the target workspace backup contains a hardcoded `workspaceId`, `capacityId`, `tenantId`, or user name/email (or if an agent working in `fabric-automation` copies a snippet from a real workspace backup into a test, fixture, or PR body), the agent is not told to strip or parameterize those identifiers. Note that `scripts/validate_docs.py`, line 242 rejects any raw GUID (`[0-9a-fA-F]{8}-...`) in any published file.
- **Evidence:** `toolchain/instructions/factory-preamble.md`, line 9 says `"into a file that this repository publishes"` (no mention of pull request text or job summaries). `toolchain/instructions/factory-preamble.md`, line 23 and `AGENTS.md`, line 27 forbid copying only `"a secret"`. `docs/reviews/instruction-layer-findings.md`, line 40 confirms: `"Not done: a general stop on identifiers in the files of the target, because item definitions in Git normally hold such identifiers"`.
