FINDINGS

F1. High. `keyvault` returns secrets and is not flagged. File: `toolchain/catalog.json`, server `azure-mcp`, `flagged` (empty). Page quote: `returning secrets (passwords) from KeyVault`. The tools page also says `keyvault` lists and creates keys, secrets and certificates. The read contract still includes `keyvault`. Read-only blocks writes, not a secret read. The generated reference then says none of its commands writes, so an agent will treat a secret read as safe. Replacement: flag `keyvault` under credentials, and say a command that returns a secret, key or certificate is never called even on the read variant.

F2. High. `role` manages RBAC and is not flagged. File: `toolchain/catalog.json`, server `azure-mcp`, `flagged`. Page quote: `View and manage Azure role-based access control`. `policy` manages policy assignments. The manifest defines `full` with no read-only switch and no flags. Replacement: flag `role` as permissions. Flag `policy` as tenant settings, or say a policy or role change through `role`, `policy`, `deploy` or `arm` is never made.

F3. High. ARM create and deploy tools can change tenant security and are not flagged. File: `toolchain/catalog.json`, server `azure-arm-cost`, `flagged`. Page quote: `Creates or updates a single Azure resource at tenant`. `create_deployment` deploys a template. Rule 6 approval is not a substitute for "never called". Replacement: flag `create_or_update_resource` and `create_deployment`, with a note that a security, permission, connection, label or tenant-setting change through them is never made. Ordinary resource creates can stay write.

F4. High. A pricesheet status tool hands out a SAS. File: `toolchain/catalog.json`, server `azure-arm-cost`, tools group read. Page quote: `time-limited SAS download URL`. Replacement: flag `get_pricesheet_status` as credentials. Do not call it from an agent.

F5. High. The warehouse tools are both "never called" and "only some statements are never run". File: `AGENTS.md`, generated flagged table; source is `catalog.json` server `fabric-sql`. Quote: `a statement that changes permissions or row-level security is never run`. Rule 10 says a tool in that table is never called. The note says the opposite for ordinary SQL. Replacement: if queries are allowed, take `executeSQL` and `execute_query` out of the never-called table and keep the limit in `needs`. If they are never called, delete the narrowing note.

F6. Medium. Foundry connection tools are not flagged. File: `catalog.json`, server `foundry-mcp`, `tools.from` `none`, `flagged` empty. Page quote: `Create or replace a project connection`. The page also names `project_connection_update` and `project_connection_delete`. Replacement: name those three and flag them as connections, or say a project connection change is never made.

F7. Medium. A local Fabric create tool can set a sensitivity label, and the schema has no label area. File: `scripts/toolchain_catalog.py` line 27, `AREAS`; lock tool `core_create-item` in the generated `fabric-local` section. Page quote: `labelId is required and must be a nonempty UUID`. Replacement: add a sensitivity-labels area, and flag a label change through `core_create-item`. A correct flag cannot be recorded today.

F8. Medium. Azure MCP stage is reversed. File: `toolchain/toolchain.json`, server `azure-mcp`, `status` `beta`. Page quote: `generally available`. Replacement: set the status from the cited page, or say the pinned package build is a beta while the product page says 2.0 is generally available. Do not print "beta" as the stage.

F9. Medium. The generator invents a read-only guarantee. File: `scripts/toolchain_catalog.py` line 579. Quote: `none of its commands writes`. That sentence is hardcoded for any `kinds: variant` server. It is not read from the catalog or from the manifest args. Today only `azure-mcp` sets it, and its read args do include `--read-only`, so the current sentence matches the manifest. Removing that arg would still generate the sentence, and the tests would pass. Replacement: emit it only when that variant's args contain the read-only switch.

F10. Medium. A generated table calls a GitHub URL a Learn path. File: `scripts/toolchain_catalog.py` line 459; result in `AGENTS.md`, others table, DataFactory row. Quote: `Documentation (learn.microsoft.com/en-us/...)`. The cell is `github.com/microsoft/DataFactory.MCP`. Replacement: head the column "Documentation" and keep the host in the cell.

F11. Medium. A missing flag passes the validator. File: `scripts/toolchain_catalog.py`, `check_against`, the flagged-name loop. Quote: `the flagged tool`. It only checks that a flagged name is one of the server's tools. `keyvault`, `role`, `create_or_update_resource` and `get_pricesheet_status` all pass. The job test at `test_CatalogTests_extract.py` line 221 only checks that already-flagged tools are absent from job variants, so a missing flag cannot fail it. Replacement: fail when a tool description or name is a credential, role, label, connection, schedule or license tool and it is not flagged.

F12. Medium. Sign-in is printed as Entra where the pages and the manifest summary do not say that. File: `scripts/toolchain_catalog.py`, `sign_in_cell`; manifest server `azure-arm-cost`. Page quote: `sign in with your Azure credentials`. The variant summary says the sign-in method is not documented. Replacement: print "not stated on the pages that were read" unless a cited page says Entra.

F13. Low. Contradictory lock annotations become a read tool. File: `scripts/toolchain_catalog.py` line 344. Quote: `read_only`. If both `read_only` and `destructive` are set, the kind is read, so a job may call it. No test sets both. Replacement: if both are set, record destructive and fail the check.

F14. Low. A directory page with no date crashes generation after the shape check passes. File: `scripts/toolchain_catalog.py` line 472. Quote: `pages[0]["updated"]`. `_pages` allows a non-Learn page with no date. No test covers that. Replacement: require the date, or omit it.

F15. Low. The fact-list test checks the same tools twice, and the first loop ignores the exemption. File: the extract of `CatalogTests` lines 291-307. Quote: `no claim of the fact list names the tool`. Replacement: delete the first loop. Also, a page-sourced server with no `page-catalog-tools-` claim is not required to have one, so an invented GitHub tool list can pass if nine other claims exist.

Checked and not raised: Fabric Core role, data-access-role and settings tools are flagged. Local Fabric data-access-role and capacity tools are flagged. Power BI `accept_eula` and `security_role_operations` are flagged. Data Factory token, service-principal, connection and schedule tools are flagged. `connection_operations` is "connect to a model", not a data-source connection tool. Fabric IQ and the SQL MCP server apply RLS; they do not change it. The operations-agent "rls" hits are the word "urls". Hosted OneLake's access-token text is client sign-in, and the page sends data-access roles to Core. Graph, consumption, ontology, notebook and data-agent pages did not show an unflagged tool that changes a flag area. `create_budget` is an ordinary cost write.
