**R-C-5 — not closed.** Run 41253985240 printed `dotnet SDK 10.0.403: dotnet tool exec does not list --yes`, and the extra `yes|-y` grep printed nothing. Learn still says “Available starting with .NET 11” (https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-tool-exec). The facts job passed `page-dotnet-tool-exec-yes`. `dnx` itself was not executed: capture wrote “5 captured”, equal to the lock, whose bicep entry is `unavailable` / `spawn-failed` / `not found`. `verify --contracts` only reprints that stored detail (`[WARN] V10: contract bicep-mcp/default is unavailable (not found)`); it does not call `which` again. `build_lock` does call `capture_contract` for every used variant when `--contracts` is set, so the equal candidate means the fresh probe also got “not found”.

`which` / `resolve_command` are behaving correctly. They search absolute PATH entries for the bare name `dnx` and never consult `DOTNET_ROOT`. A miss is LaunchError 127, “not found”. Learn says `dnx` is “a shell script provided by the installer and available on PATH.” The ubuntu-24.04 image readme lists .NET SDK 10.0.403 and does not list `dnx` (https://github.com/actions/runner-images/blob/main/images/ubuntu/Ubuntu2404-Readme.md). So this is not a kit path-search bug. It is a wrong assumption that the image’s SDK implies `dnx`, plus a launch flag that this SDK’s `dotnet tool exec` does not offer. Putting `dnx` on PATH would still leave `--yes` unproven and, per Learn and the help text, unsupported on 10.0.403. The Bicep page still shows `dnx -y Azure.Bicep.McpServer` for the .NET 10 SDK (https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/bicep-mcp-server), flag before the package and no version. The kit runs `dnx Azure.Bicep.McpServer@0.48.1 --yes`. That order difference is UNVERIFIED because `dnx` never started.

The comment that the image ships the .NET 10 SDK “for dnx” is false. The SDK is on the image. `dnx` is not on PATH. Smallest honest change: drop “for dnx”; record `command -v dnx`; stop passing `--yes` until a .NET 10 non-interactive form is proven, or require .NET 11 for this server; say in the README that the help text has been read and does not list `--yes`.
