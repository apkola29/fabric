## FINDINGS

- **F1** (Low) — `CLONE4\new\scripts\toolchain_catalog.py`, lines 46–47 and 441–444 (`AREA_WORDS` and `unflagged_tools`).
  - Quote: `needed |= WORD_AREAS.get(word, set(AREAS))`
  - Issue:
    1. When a tool name contains both `"modify"` (`GENERIC_WORDS`) and an area-specific word in `WORD_AREAS` (such as `diagnostics`, `immutability`, `policy`, or `tier`), `WORD_AREAS.get("modify", set(AREAS))` returns `set(AREAS)` (all 9 areas) and `needed |= ...` unions all 9 areas into `needed`, wiping out the area restriction of the specific word. In the committed catalog, all 5 tools that contain `"modify"` (`onelake_modify-diagnostics`, `onelake_modify-immutability-policy`, `onelake_modify_default_tier`, `onelake_modify_diagnostics`, `onelake_modify_immutability_policy`) also contain `diagnostics`, `immutability`/`policy`, or `tier`; for all 5 of them `needed` evaluates to all 9 areas, so flagging any of them under an unrelated area (e.g., `license` or `schedules`) passes `unflagged_tools`.
    2. When `kind == "read"`, a tool is `risky` only because of `words & SECRET_WORDS` (which belong exclusively to `"credentials"`), yet `needed` loops over `words & PROTECTED_WORDS`. A `read` tool whose name contains both a secret word and a non-secret protected word (e.g., `get_connection_token` or `get_schedule_secret`) gets `needed = {"connections", "credentials"}` or `{"schedules", "credentials"}` and passes `unflagged_tools` if flagged only under `connections` or `schedules`.
    3. In `AREA_WORDS` (lines 46–47), `"policy"` is in both `"security settings"` and `"capacity, tenant or workspace settings"`, but its plural `"policies"` is only in `"security settings"`.
  - Suggested replacement: Add `policies` to `AREA_WORDS["capacity, tenant or workspace settings"]`, and in `unflagged_tools` compute `needed` from the active words and fall back to `set(AREAS)` only when no word in the name maps to a specific area in `WORD_AREAS`:
    ```python
            active = (words & SECRET_WORDS) if kind == "read" else (words & PROTECTED_WORDS)
            needed = set().union(*(WORD_AREAS[w] for w in active if w in WORD_AREAS)) or (set(AREAS) if active else set())
    ```

- **F2** (Low) — `CLONE4\new\scripts\toolchain_catalog.py`, lines 517–524 (`check_against`, `PROTECTED_REVIEWED` check).
  - Quote: `and the catalog flags it: drop the exception`
  - Issue:
    1. `elif any(name in e["tools"] or any(name in re.findall(r"`([^`]+)`", c) for c in e.get("changes", [])) for e in server["flagged"]):` checks whether `name` appears under *any* area of `server["flagged"]`, whereas `unflagged_tools` requires `name` to be covered under an area in `needed`. If a tool `(sid, name)` is in `PROTECTED_REVIEWED` because a misleading word in its name maps to Area A (`needed = {Area A}`), while `name` is legitimately named in a `changes` statement under Area B (`Area B not in needed`), `check_against` reports `"and the catalog flags it: drop the exception"`; if the maintainer drops the exception, `unflagged_tools` then fails because `covered[name] & needed` is empty.
    2. Conversely, if an entry in `PROTECTED_REVIEWED` names a `read` tool without `SECRET_WORDS` or a tool without `PROTECTED_WORDS`, `check_against` does not report that the exception is unnecessary.
  - Suggested replacement: Add an optional `ignore_reviewed=False` parameter (or check whether `name` would be flagged by `unflagged_tools` without `PROTECTED_REVIEWED`) and replace the `elif` in `check_against` with:
    ```python
        elif name not in unflagged_tools(server, lock, reviewed=()):
            problems.append("server %s: the tool %s is reviewed and left out of the check of protected names, and it needs no exception: drop the exception" % (sid, name))
    ```

- **F3** (Low) — `CLONE4\new\verification\tools\catalog_quotes.py`, lines 262–282 (`lists`).
  - Quote: `if n in found or n not in mine`
  - Issue:
    1. `unread` checks only `s["id"] not in {sid for sid, _set in union}`, not `(s["id"], g.get("set"))` pairs. If a server that already has a `(sid, None)` entry in `LISTS` has an additional named `set` in `catalog.json` (or if `("azure-arm-cost", "optional Cost Management toolset", ...)` is removed from `LISTS`), `lists` checks only `g.get("set") == None` and silently ignores the named set without reporting `DIFF`.
    2. `absent` checks `n not in mine` inside the `(sid, tool_set)` loop where `mine` holds only the tools of `tool_set`, while `NOT_ON_THE_PAGE` is keyed only by `sid`; for any server with multiple tool sets in `LISTS` (such as `azure-arm-cost`), a set-aside tool in one set fails `n not in mine` on the other set.
  - Suggested replacement: Check `NOT_ON_THE_PAGE` against the full tool list of `by_id[sid]` (or key `NOT_ON_THE_PAGE` by `(sid, tool_set)`), and check that every `(s["id"], g.get("set"))` in `catalog["servers"]` with `tools["from"] == "page"` is covered in `union` (unless ` (s["id"], None)` fell back to all groups).
