## 1. Diff Review (`a7932d1..abe6b9d614`, Slice 1: `scripts/toolchain.py` and `scripts/test_toolchain.py`)

The delta adds 494 lines to `scripts/toolchain.py` and 1,808 lines to `scripts/test_toolchain.py` (535 tests; 534 pass and 1 symlink test is skipped on unprivileged Windows). Reading the diff in full and testing the real seams between `toolchain.py` and its three helper modules (`toolchain_io.py`, `toolchain_mcp.py`, `toolchain_sources.py`) surfaced five structural patterns where a fix is incomplete, differs from its test, or breaks at a module seam:

1. **Seam mismatches between `toolchain.py` and `toolchain_mcp.py` / `toolchain_sources.py`.**
   - `probe_environment` (`scripts/toolchain.py`, lines 1703–1718) pre-evaluates `spec` against `base` using `base.get(item["from_env"], item.get("default"))` and passes a flat `{name: str}` map to `toolchain_mcp.probe_stdio` -> `capture_env`. When an operator variable is set to `""` (empty string, common in CI workflows), `probe_environment` passes `""` instead of falling back to `default` or omitting the variable, bypassing `toolchain_mcp._declared_value` (`scripts/toolchain_mcp.py`, lines 136–150), whose `dict` branch is now unreachable from `toolchain.py`.
   - `bounded_environment` (`scripts/toolchain.py`, lines 1771–1779) strips case-insensitive `BOUND_VARIABLES` from `env`, and `ContractCheckTests` (`scripts/test_toolchain.py`, lines 3383–3395) claims to test that operator `NPM_CONFIG_BEFORE` and `uv_exclude_newer` entries are replaced. Because `probe_environment` now strips undeclared operator variables before `bounded_environment` is called, `bounded_environment`'s case-insensitive removal is never exercised by the test suite (mutating line 1777 to `bounded = dict(env)` survives all 535 tests).
   - `SERVER_VERSION_RE`, `SERVER_NAME_RE`, and `TOOL_NAME_RE` (`scripts/toolchain.py`, lines 93–97) were written separately from `toolchain_mcp._suspect` (`scripts/toolchain_mcp.py`, lines 332–335). Neither module checks `_suspect` on tool names, so a tool named after a private host, an IPv4 address, or a 36-character token passes both `probe_stdio` and `capture_contract` into `toolchain.lock.json`.
2. **`cmd_fetch` does not use `resolve_profile` or `profile_findings`.** While `render` and `install` call `resolve_profile`, `cmd_fetch` (`scripts/toolchain.py`, lines 2847–2865) duplicates a subset of checks (`select_skills`, `select_shared`, `repo_skill_findings`) and omits V8 upstream skill lint failures in `agent` mode and V2 repo-owned skill name collisions. Meanwhile, `toolchain/README.md` (line 81) states that V11 stops "every command, not only `verify`", which is false for `fetch`, `list`, and `doctor`.
3. **Link and file-type gaps in `lock`, `update`, `install`, `verify --live`, and `doctor`.**
   - `refuse_store_links` was added to `cmd_fetch` and `store_op`, but never to `cmd_lock` or `cmd_update` (`build_lock` -> `resolve_source`, `scripts/toolchain.py`, lines 1663–1699), which create and `remove_tree` `.factory/pack/.cache/<commit>` through a junction at `.factory`.
   - `copy_tree` (`scripts/toolchain.py`, lines 2899–2909) checks `.is_symlink()` (which is `False` for Windows junctions) instead of `is_link()`, and never checks `is_link(source)`. `repo_skill_folders` (`scripts/toolchain.py`, lines 1986–1995) and `instruction_problems` (`scripts/toolchain.py`, lines 1252–1261) also traverse junctions/symlinks on `toolchain/skills/factory-router` and `toolchain/instructions`.
   - `_has_content` (`scripts/toolchain.py`, lines 3024–3029) catches `toolchain_sources.SourceError` only for unmanaged folders (`name not in managed`), leaving `deps.digest_tree` uncaught in the managed branches of `_managed_ops` (lines 3059 and 3074), `skills_dir_problems` (lines 2356 and 2368), and `store_problems` (lines 2032 and 2041).
4. **PEP 440 pre-releases in `read_version` / `at_pin`.** `EXACT_VERSION_RE` (`scripts/toolchain.py`, line 84) permits PyPI pre-releases without a hyphen (`1.8.0rc1`, `1.8.0a1`), but `read_version` (`scripts/toolchain.py`, lines 3269–3272) requires `[-+]` before a suffix, silently stripping `rc1`/`a1` and reporting `1.8.0rc1` as equal to the `1.8.0` pin.
5. **A test that passes when the production action is deleted.** In `remove_tree` (`scripts/toolchain.py`, lines 208–214), `test_what_is_removed_has_its_read_only_attribute_cleared_on_windows_and_its_mode_left_alone_elsewhere` (`scripts/test_toolchain.py`, lines 4021–4038) invokes `onerror` on a writable file and then runs the real `shutil.rmtree`. Deleting `function(target)` from `retry` in `remove_tree` passes all 535 tests while breaking deletion of read-only files on Windows.

### R-D1-2 Medium. `read_version` and `at_pin` strip PEP 440 pre-release suffixes (`1.8.0rc1`, `1.8.0a1`), passing pre-releases as the pinned release in `verify --live` and `doctor`

- **Where:** `scripts/toolchain.py`, lines 84 and 3269–3285.
- **What is wrong:** `EXACT_VERSION_RE` (`scripts/toolchain.py`, line 84) explicitly accepts PEP 440 pre-release versions without a hyphen or plus sign (`(?:-|\+|(?=[A-Za-z]))[0-9A-Za-z][0-9A-Za-z.+-]*`), which PyPI packages such as `ms-fabric-cli` (`fab`) use (`1.8.0rc1`, `1.8.0a1`, `1.8.0b2`). However, `read_version` (`scripts/toolchain.py`, line 3271) uses `r"(\d+(?:\.\d+)+)([-+][0-9A-Za-z][0-9A-Za-z.+-]*)?"`, requiring a leading `-` or `+` for group 2. When `fab --version` prints `fab 1.8.0rc1`, `read_version` returns `((1, 8, 0), "")`, dropping `rc1`.
