## How the uncertain points were checked

- **Several push addresses (R4-A-1).** A scratch repository was given a second push address with `git remote set-url --add --push`. `get-url --push` printed one address and `get-url --push --all` printed both.
- **What was scanned against what was pushed (R4-A-2).** The reviewer's fixture was an in-memory simulation, so the author checked the sequence in the script and then pinned it with a behavioural test: the scan of the source, the scan of the mirrored copy, the staging, the commit, the tree check and the push must happen in that order, and a failed scan of the mirror must stop everything after it.
- **Entries that are not regular files (R4-A-3, R4-A-4).** Tests put a gitlink and a symbolic link into the index with `git update-index --cacheinfo`, which needs no file system support for links, and they failed against the code as it was.
- **Test counts (R4-C-2).** `git diff` of the test file between the two commits shows 20 added and 1 removed definitions, and counting the definitions in each commit gives 41 and 60.
- **The webhook actions.** The static GitHub page lists only the first action of each event (`added` for membership, `added_to_repository` for team), so the design's statements about a removed member and an edited team were not backed by the page that the fact cited. The actions exist, and at the time they were confirmed from the webhook payload schemas of the Octokit repository. This record then described those schemas as generated from GitHub's payloads, which was wrong: the repository's own README calls them hand-crafted and no longer maintained. Round 5 found this (R5-C-2) and replaced the two entries with one that reads GitHub's own OpenAPI description, which lists the same actions.

## Found while fixing (not raised by a reviewer)

1. **`robocopy /MIR` deletes what a junction in the destination points to, even with `/XJ`.** The reviewer listed junction deletion as unverified. A test in a temporary folder showed that the files behind the junction were gone after the mirror, and the original script had the same exposure. The script now refuses to mirror into a clone that holds a link (found by link type, so that OneDrive placeholders are not mistaken for links), the purge never walks through a link, the validator flags links and junctions in the project, and a test with a real junction checks that nothing behind it is deleted.
2. The first version of the junction test passed `/XJ` and still failed, which is what showed that `/XJ` does not protect the destination. Passing the flag was the first fix and was not enough.
