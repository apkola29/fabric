# Verification round 6: findings and what was done

Round 6 was a closure check of what round 5 changed (commit `f6ed0fc4de`), cut into three slices, one per model family, with the slices handed to different families than in round 5: GPT 6.1 Sol on the publish script and its behavioural tests ([round-6-gpt.md](round-6-gpt.md)), Gemini 4 Argon on the Python tooling ([round-6-gemini.md](round-6-gemini.md)), and Grok 4.7 on the fact list, the design edits, the records, the public exposure and a cold read ([round-6-grok.md](round-6-grok.md)). The two reviewers on code mutated the safeguards to see which tests noticed. None of them had seen an earlier round. The loop is recorded in [verification-log.md](verification-log.md), and round 5 is in [round-5-findings.md](round-5-findings.md).

Every finding was checked against the text, the code or the primary source before it was accepted, and the severity below is the author's after that check. A finding about code was reproduced against the code as published, usually by a test that failed there, and then fixed. Every safeguard that was changed or claimed was then removed from a copy, one at a time, and a test had to fail.

## How the fixes were made

The fixes to the publish script and its tests were made by the author. The fixes to the validator, and to the fact checker and the commit checker, were written test-first by two agents, each in an isolated copy of the project and from a specification that the author had written after reproducing the findings. The author reviewed every diff, copied the files into the project, ran the suites again and ran the mutations again. Where an agent went beyond the specification, the author kept what was right: an empty tree listing is unreachable (the fact checker), the differential test of the ignore rules sets Git's case folding explicitly and has two more files, because two of its mutations had survived the old file list, and the linear form of the path patterns, which corrected a flaw in the specification itself.

## What this round did not close

- The round-6 changes themselves have not been reviewed by a model of another family. They were checked by tests, by mutations and by the author's reproductions.
- The publish-flow tests need Windows, so they have never run on the hosted runner, and the tests that need a file symbolic link run only on the hosted Linux runner. This account cannot create a symbolic link.
- The leak scan matches ASCII text. The allowlist of non-ASCII characters is short on purpose, and a new character has to be added to it by hand.
- Case folding of the ignore rules is not modelled. A file whose status would depend on it is refused.
- Nothing here has been tested on a live tenant, and the spike outputs at the end of [round-3-findings.md](round-3-findings.md) are still open.
