## FINDINGS

### F1 — Low — `CLONE5\new\scripts\toolchain_catalog.py`, lines 43–51 (`AREA_WORDS`, `GENERIC_WORDS`) and lines 430–451 (`unflagged_tools`); `CLONE5\new\scripts\test_CatalogTests_extract.py`, lines 501–522
- **Quote**: `"permissions": "role roles permission permissions grant revoke share invite assign acl",`
- **Problem**:
  1. `assign` is placed in `AREA_WORDS["permissions"]` rather than `GENERIC_WORDS`. In the committed catalog, the only tool whose name contains `assign` is `core_assign-workspace-to-capacity` (`fabric-local`), which belongs to `"capacity, tenant or workspace settings"`, not `"permissions"`. Because `WORD_AREAS["assign"]` is `{"permissions"}`, `needed` for `core_assign-workspace-to-capacity` becomes `{"capacity, tenant or workspace settings", "permissions"}`, so if `core_assign-workspace-to-capacity` (or `assign_capacity`) is mistakenly flagged under `"permissions"` instead of `"capacity, tenant or workspace settings"`, `unflagged_tools` lets it pass.
  2. In `unflagged_tools`, `needed` takes the union across all words in `active` (`needed |= WORD_AREAS.get(word, set())`) and checks `not (covered.get(name, set()) & (needed or set(AREAS)))`. When a tool name contains two specific words, covering only one of them satisfies `unflagged_tools` and ignores the other:
     - A `write`, `destructive` or `mixed` tool whose name contains both a secret word and another area's word (for example `get_connection_token` with `kind="mixed"` or `set_connection_token` with `kind="write"`) passes `unflagged_tools` when flagged only under `"connections"` (without `"credentials"`), even though the same `get_connection_token` with `kind="read"` is rejected.
     - In the committed catalog, `security_role_operations` (`powerbi-authoring-local`, `mixed`) has `active = {"role", "security"}`. Because `needed` is the union `{"permissions", "row-level or object-level security", "security settings"}`, flagging `security_role_operations` under `"security settings"` alone (ignoring `role`) or `"permissions"` alone (ignoring `security`) passes `unflagged_tools`, whereas requiring each specific word to be covered pins it to `"row-level or object-level security"`.
- **Suggested replacement**: Move `assign` from `AREA_WORDS["permissions"]` into `GENERIC_WORDS` (`GENERIC_WORDS = frozenset(["modify", "assign"])`), and in `unflagged_tools` require every specific word in `active` to be satisfied by `covered`:
  ```python
  specific = [w for w in active if w in WORD_AREAS]
  ok = all(covered.get(name, set()) & WORD_AREAS[w] for w in specific) if specific else bool(covered.get(name, set()))
  if not ok and (server["id"], name) not in reviewed:
      out.append(name)
  ```
  (All 24 servers of the committed catalog pass this stricter check without change.)

### F2 — Low — `CLONE5\new\verification\tools\catalog_quotes.py`, line 204 (`LISTS`) and lines 269–296 (`lists`)
- **Quote**: `left = (sets - covered) if None in sets else`
- **Problem**: `operations-agent-remote` has two named tool sets in `catalog.json` (`"configure URL"` and `"query URL"`), corresponding to two separate tables (`### Configure server` and `### Query server`) on `en-us-fabric-real-time-intelligence-mcp-remote-operations-agent.md`, but `LISTS` still reads it with a single `(sid, None)` entry (`("operations-agent-remote", None, ..., "Configure server", "\n## ", "table")`). To accommodate that single `None` entry, `lists()` keeps two special-case fallbacks: flattening all groups when `tool_set is None and not mine` (lines 269–270), and setting `left = set()` whenever `None in covered` and `None not in sets` (line 294). As a result:

  2. Adding a new named set to `operations-agent-remote` in `catalog.json` without an entry in `LISTS` is hidden because `None in covered` forces `left` to `set()`.
- **Suggested replacement**: Split `operations-agent-remote` in `LISTS` into its two named sets:
  ```python

  ```
  Then remove `if tool_set is None and not mine:` in `lists()` and simplify line 294 to `left = sets - covered`.
