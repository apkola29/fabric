## How the uncertain points were checked

- **The order of the pinned check (R3-B-1).** The rulesets page lists three conditions for an App to be the required source: the statuses write permission, a recent check run, and an association with a pre-existing required check in the ruleset. It gives no order. The order now written satisfies every reading of it, and S11 confirms it on a real repository.
- **Drafts (R3-B-3).** GitHub's page on the stage of a pull request says that people with write permission and the author can change it, and that no one can merge until it is marked ready. The GraphQL schema has a mutation in each direction. The REST call that updates a pull request takes a title, a body, a state, a base and a maintainer flag, and no draft flag.
- **Check conclusions (R3-B-4, R3-B-5).** GitHub's troubleshooting page says that success, skipped and neutral are successful, that a check on an earlier commit does not count, and that a check and a status with the same name must both pass. Nothing says what happens to a failed check when the App is suspended.
- **Two caps with one name (R3-B-7).** The research report that the budget text relied on cites the Copilot SDK's session-limit page, where the cap is soft ("one response can exceed the configured value"). gh-aw's own documentation calls `max-ai-credits` a hard stop, one credit is one US cent, and pricing is best-effort. The proxy's guard adds a response's cost after the response arrives, refuses later requests once the total reaches the cap, has an absolute ceiling of 10,000 credits, and warns that unpriced usage may be undercounted. That requests already in flight can finish is read from the code and not documented, so S9 measures it.
- **The 404 for a missing folder (R3-B-2).** The REST reference lists five error codes and none for this. The public skill says, in one sentence, that the call does not create the folder and fails with a 404 `GitProviderResourceNotFound`.
- **The reviewer's link.** One address that Grok cited for the status-check page returns 404 today. The statements it attributed to that page are on the page linked in its reply file, which the author read directly.

## Found while fixing (not raised by a reviewer)

1. A UTF-16 private list written without a byte-order mark decoded as UTF-8 with NUL characters between the letters, so every term in it would have matched nothing and the list would still have counted as non-empty. It is now refused.
2. The validator's address pattern flagged the SSH user of a Git remote, which the publish script's own error message contains. That one address is now allowed exactly, and look-alikes are still flagged.
3. A round-2 test of the fact checker pinned a wrong behaviour: a 500 answer from a documentation page was a FAIL. It is now UNREACHABLE, and only "not found" fails.
4. The ignore matcher treated a wildcard folder rule such as `tmp*/` as a literal name.
5. Three fact entries described the proxy ceilings and the draft in terms that the corrections had made stale. Their claims were rewritten, and 10 entries were added for the statements that this round turned on.
