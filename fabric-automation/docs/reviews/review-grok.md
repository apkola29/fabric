# Design review: Grok 4.7 (lens: red team)

Date 2026-10-30. Reviewer: Grok 4.7 (`rubber-duck` agent, read-only, web access). Reviewed `04-design.md` v0.1 against the requirements, decision register, landscape digest and verification results. Transcribed by the orchestrator in condensed form from the reviewer's inline reply.

Result: 18 findings. 2 CRITICAL, 8 HIGH, 7 MEDIUM, 1 LOW, plus a list of missing detections. The reviewer's summary: the trust split is the right shape, but several controls are bypassable as specified. The two critical holes are agent-chosen executor arguments and a Phase 0 runtime that cannot keep secrets and egress away from the agent.

Missing detection (the reviewer's list, none of it in section 3.16): alert on output-gate rejects, unsigned commits to `factory/*`, ledger non-fast-forward updates, requester equals approver, a secret or PII in an issue before the model call, capacity left resumed, refresh capacity use over the ceiling, and any workspace on the sandbox capacity that is not in the registry.

## What the reviewer found strong

- Agents propose and a different principal disposes. Do not give the agent a Fabric token to simplify Phase 0.
- Deterministic gates decide. Verifiers may only add blocks.
- T3 is refused. The factory never merges, approves or promotes.
- Path B for validation, so the Git credential is not needed on the test path.
- Two Fabric identities, a sandbox capacity separate from everything else, and an explicit escalate action.
- Spikes S2, S5 and S7 are exit criteria, not optional labs.

## Reviewer's top five changes before Phase 0

1. Executor arguments and the workspace registry are orchestrator-owned. Agents pass a run ID only.
2. No model or Git token in the agent job, and no Phase 1 until egress deny is demonstrated. Do not treat the Copilot shell firewall as C4.
3. Freeze spec, fixtures and oracles against the implementer. Hidden tests never enter workflow artifacts.
4. No write-capable Git credential in a Fabric connection. Prefer path B for dev-sync.
5. Fail closed: a pre-model intake scan, an alias allow-list, a requester-is-not-approver check, and C8, C12 and C13 before any live issue is processed.

## Residual risks the reviewer says the design should state

- A human can still merge a wrong but plausible measure. Gates do not understand business intent. Client-side report features are outside outbound access protection.
- The personal proof of concept has no real separation of duties. One operator can disable every ruleset.
- Grok retention terms are unverified. A pasted customer row is already a disclosure, even if the form says synthetic.
- Preview Git and outbound access protection can change under a pin, and contract tests will lag.
- Held-out tests are finite. A T1 change can hard-code the visible example and still pass.
- Soft-deleted workspaces keep billing and can come back with new IDs. GitHub and Entra remain fully trusted control planes.
