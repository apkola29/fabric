# Slice B Review: Server Catalogue, Commands, Mutation Tests, and Windows vs. Linux

## Summary of Slice B Checks

1. **Catalogue against the truth (`AGENTS.md`, `toolchain/toolchain.json`, and primary sources):** All 11 servers in `toolchain/toolchain.json` appear in the first table of `AGENTS.md` with matching IDs and non-default variant names, and all 14 entries of the Microsoft Learn Fabric MCP server directory (`https://learn.microsoft.com/en-us/rest/api/fabric/articles/mcp-servers/fabric-mcp-servers-list`, updated `2026-10-21`) plus its two related customer-hosted entries appear across the two tables and line 52 of `AGENTS.md`. However, there are sign-in inaccuracies for `powerbi-authoring-local` (B-3), a wrong documentation target and per-item count for `Operations agent, remote` (B-5), omitted capabilities on three pinned servers (B-11), and four Microsoft-official MCP servers relevant to Fabric/Power BI/Azure that neither the directory table nor `AGENTS.md` lists (B-4).
2. **Commands on a fresh clone:** Every `python scripts/toolchain.py ...`, `validate_docs.py`, and `unittest` command in the instruction layer was run in `scratch-B/fabric-automation` (a fresh copy without `.factory` or `.github/skills`).
   - **Needs network / creates `.factory`:** `update --check --fail-on-update --summary-file FILE` requires GitHub/registry network access, creates `.factory/pack/.cache/<commit>` by cloning both upstream skill repos on every run, and writes an unignored `FILE` in the working directory that breaks `validate_docs.py --strict` (B-1). `install --apply` requires network on a fresh clone to populate `.factory/pack`. `doctor` (without `--offline`) runs `gh auth status`, `az account show`, and HTTP probes to the 5 hosted servers in `dev-factory`.
   - **Offline / no `.factory` needed:** `verify`, `verify --offline`, `list`, `list --profile dev-factory`, `render --host load-plan --profile dev-factory`, and `install` (dry-run plan) all exit `0` offline without `.factory`. However, `verify` (without `--live`) and `list` do **not** check whether `.factory/pack` or `.github/skills` exists on disk, so a fresh clone with zero installed skills passes `verify` with `0 failure(s), 6 warning(s)` (B-2). Furthermore, `render --host load-plan --profile NAME` (`GEMINI.md`, line 5) exits `0` for `dev-*`, `agent-planner`, and `agent-test-author`, but exits `1` for `agent-implementer`, `executor-static-gates`, and `executor-sandbox-read` because `powerbi-authoring-local` has `status: "skipped"` in the lock.
3. **Tests by mutation (`(a)`–`(m)` against `InstructionLayerTests` and `RouterGuardTests`):**
   - **Caught (failed tests as expected):** `(a)` delete row of first table; `(b1)` change single-variant sign-in cell `Entra` -> `none`; `(c)` rename variant `read` -> `readonly`; `(d)` add `@` import line to `AGENTS.md`; `(e)` add `#` heading to `CLAUDE.md`; `(f1)` break flag `--summary-file` -> `--bogus-flag` in preamble; `(g1)` change the single freshness command in `factory-router/SKILL.md`; `(h1)` add unknown back-ticked kebab-case name in `AGENTS.md`; `(i1)` remove license rule from `factory-preamble.md`; `(j1)` delete second table in `AGENTS.md`; `(k1)` move `fabric/iq/connectors/fabric-iq-mcp` into second table; `(l)` make `AGENTS.md` > 100 lines.
   - **Missed (all 19 tests in `InstructionLayerTests` and `RouterGuardTests` passed):** `(b2)` swap variant sign-in mapping inside `fabric-local` or `powerbi-authoring-local` cell; `(b3)` change `Entra` to `Entra or service principal` on `fabric-iq`; `(d2)` add a second `@OTHER.md` import to `CLAUDE.md`, `GEMINI.md`, `factory-preamble.md`, or `factory-router/SKILL.md`; `(f2)` pass nonexistent `--profile no-such-profile` in a command or break a flag on `validate_docs.py`; `(f3)` corrupt subcommand `doctor` -> `--doctor` so `COMMAND` regex skips it; `(g2)` change one of the two copies of the freshness command in `AGENTS.md`; `(h2)` add unknown back-ticked kebab-case name (or broken command) in `factory-standards/SKILL.md`; `(i2)` delete the license rule or the entire `## Rules` section from `AGENTS.md`; `(j2)` replace a server name and description in the second table while keeping its doc path; `(k2)` move a pinned server whose directory URL has a `#fragment` or differs from `toolchain.json`'s `docs` entry into the second table; `(m)` misspell single-word back-ticked names (`fabriciq` -> `fabriciqx`, `bicep` -> `bicepx`, `fab` -> `fabx`), swap a skill name into the server column of `factory-router/SKILL.md`, delete the entire `## 2. ## Findings

### B-1 (High): Session-start freshness command writes an unignored summary file that breaks `validate_docs.py --strict` and re-clones both skill repos on every session
- **Where:** `AGENTS.md`, lines 12 and 70; `toolchain/instructions/factory-preamble.md`, line 39; `toolchain/skills/factory-router/SKILL.md`, line 20; `.gitignore`, lines 1–27.
- **What is wrong:** All three instruction files tell the agent at the start of every session to run `python scripts/toolchain.py update --check --fail-on-update --summary-file FILE`. First, `update --check` already prints the full gap report to `stdout` (`scripts/toolchain.py`, line 2948); `--summary-file` writes an additional Markdown file on disk (`scripts/toolchain.py`, line 2950). If an agent runs the command with literal `FILE` (or any filename in the working directory not matching `tmp*` or `*.tmp`), the file is not ignored by `.gitignore`. A file without an extension in `TEXT_SUFFIXES` (such as `FILE`) causes `python scripts/validate_docs.py --strict` (`AGENTS.md`, line 72) to fail with exit `1`; a `.md` or `.txt` file in the project folder passes `validate_docs.py` and is treated by `publishable_files()` (`scripts/validate_docs.py`, line 117) and `scripts/sync_to_github.ps1` (line 206) as a tracked repository file to commit and publish. Second, `cmd_update` calls `build_lock()` -> `resolve_source()`, which deletes and re-fetches both upstream Git repositories (`microsoft/skills-for-fabric` and `microsoft/azure-skills`) over the network into `.factory/pack/.cache/<commit>` on every run (~20 seconds, and fails with exit `1` if GitHub is unreachable).
- **Evidence:** Ran in `scratch-B\fabric-automation`:
  ```powershell
  python scripts/toolchain.py update --check --fail-on-update --summary-file FILE
  python scripts/validate_docs.py --strict
  ```
  Observed: `update --check` created `.factory\pack\.cache\4c3986d2...` and `.factory\pack\.cache\fbda857c...` and wrote `FILE`; `validate_docs.py --strict` exited `1` with `[ERROR] unscanned-file FILE: the leak scan does not read this type of file, so it must not be published (remove it, or ignore it in .gitignore)`.
- **Suggested fix:** For interactive sessions in `AGENTS.md`, `factory-preamble.md`, and `factory-router/SKILL.md`, either drop `--summary-file FILE` (relying on `stdout`) or set the path inside the git-ignored `.factory/` directory (for example `--summary-file .factory/update-summary.md`).

### B-2 (High): `verify` and `list` pass on a fresh clone with zero installed skills, contradicting `AGENTS.md`
- **Where:** `AGENTS.md`, lines 9–10 and 69; `toolchain/skills/factory-router/SKILL.md`, lines 16–18; `scripts/toolchain.py`, lines 2551–2590 and 2725–2726.

Likewise, `list --profile NAME` only formats the manifest and lock data (`scripts/toolchain.py`, lines 2784–2832). On a fresh clone before `install --apply` has run, both `verify` and `list` exit `0` and report 58 skills and 8 servers, giving the agent no signal that nothing is installed on disk.
- **Evidence:** Ran in `scratch-B\fabric-automation` (where `.factory` and `.github/skills` do not exist):

### B-3 (Medium): `AGENTS.md` sign-in rules contradict `powerbi-authoring-local` variants and upstream documentation
- **Where:** `AGENTS.md`, lines 24 and 33; `toolchain/README.md`, lines 10 and 111; `toolchain/toolchain.json`, lines 191–204.
- **What is wrong:** `AGENTS.md`, line 24 states: `"Servers marked Entra are hosted and act as the person who signed in with a browser. Servers marked Azure identity use the identity of az login, or of the job."` Both sentences are false for `powerbi-authoring-local` (`AGENTS.md`, line 33: `` | `powerbi-authoring-local` (`offline-readonly`, `service-readonly`, `interactive`) | none; Azure identity; Entra | ... | ``):
  1. `powerbi-authoring-local` (`interactive`) is marked `Entra` (`"credentials": "entra-delegated"` in `toolchain/toolchain.json`, line 203), but it is a **local `stdio`** server (`npx -y @microsoft/powerbi-modeling-mcp@1.0.0 --start`), not a hosted server, and opens a local interactive sign-in rather than a browser OAuth handshake to a hosted MCP endpoint.
  2. `powerbi-authoring-local` (`service-readonly`) is marked `Azure identity` (`"credentials": "azure-identity"` in `toolchain/toolchain.json`, line 198) and passes `--authmode=serviceprincipal`. Unlike `fabric-local`, `azure-mcp`, and `fabric-rti-local` (which use `DefaultAzureCredential` and accept `az login`), `@microsoft/powerbi-modeling-mcp` in `--authmode=serviceprincipal` requires explicit `AZURE_CLIENT_ID`, `AZURE_TENANT_ID`, and `AZURE_CLIENT_SECRET` (or `AZURE_CLIENT_CERTIFICATE_PATH`) environment variables and does **not** use `az login`.
- **Evidence:** Primary source `https://github.com/microsoft/powerbi-modeling-mcp/blob/main/README.md` (Settings table): `"--authmode | interactive | Set authentication mode: serviceprincipal or interactive"` and `"AZURE_CLIENT_ID | The application (client) ID of the Microsoft Entra service principal. Required when --authmode=serviceprincipal."`
- **Suggested fix:** Revise `AGENTS.md`, line 24 and `toolchain/README.md`, lines 10 and 111 to say that `Entra` means interactive user sign-in (browser OAuth on hosted servers, or interactive Entra sign-in on `powerbi-authoring-local`), and `Azure identity` means `az login` or workload/service-principal credentials (`service-readonly` on `powerbi-authoring-local` requires service-principal environment variables, not `az login`).

### B-9 (Medium): Command and freshness tests in `InstructionLayerTests` miss mutated second copies, corrupted subcommands, invalid `--profile` names, and `validate_docs.py`
- **Where:** `scripts/test_toolchain.py`, lines 7745–7746, 7759–7761, 7791–7802, and 7814–7817.
- **What is wrong:**
  1. **Mutation (g) gap:** `test_the_freshness_command_is_the_same_in_every_file_that_gives_it` uses `self.assertIn(self.FRESHNESS, self.text(path))`. Because `AGENTS.md` contains the freshness command **twice** (line 12 under "Start of every session" and line 70 under "Commands"), mutating one of the two copies in `AGENTS.md` (e.g., removing `--fail-on-update` on line 12 while line 70 stays intact) passes `assertIn` and also passes `parse_args`.
  2. **Mutation (f) regex gap:** `COMMAND = re.compile(r"python scripts/toolchain\.py[ \t]+([a-z]+)([^`\r\n#]*)")` requires a lowercase subcommand token immediately after `toolchain.py`.
