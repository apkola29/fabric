# Verification round 5: findings and what was done

Round 5 was a closure check of what round 4 changed (commit `c7c690a0eb`), cut into three slices, one per model family: Gemini 4 Argon on the publish script and its behavioural tests ([round-5-gemini.md](round-5-gemini.md)), Grok 4.7 on the Python tooling ([round-5-grok.md](round-5-grok.md)), and GPT 6.1 Sol on the fact list, the design edits, the records, the public exposure and a cold read ([round-5-gpt.md](round-5-gpt.md)). The two reviewers on code mutated the safeguards to see which tests noticed. None of them had seen an earlier round. The loop is recorded in [verification-log.md](verification-log.md), and round 4 is in [round-4-findings.md](round-4-findings.md).

Every finding was checked against the text, the code or the primary source before it was accepted, and the severity below is the author's after that check. A finding about code was reproduced by a test that failed against the code as published, and then fixed. The reviewers on code found that the tests had not pinned some of the safeguards, so the fixes also include a mutation run: every safeguard that was changed or claimed was removed from a copy, one at a time, and a test had to fail.

## How the uncertain points were checked

- **Webhook text (R5-C-1).** The page text between the two markers was printed. The word matched in "team memberships" and "Team members", and the permission sentence is the third match.
- **Octokit (R5-C-2).** The README was fetched. Its warning calls the repository "woefully out of date and not maintained anymore" and its schemas hand-crafted, and points to the OpenAPI repository. GitHub's OpenAPI description (13.9 MB) has the five operations, each exactly once, under its webhooks key.
- **The ignore rules (R5-B-5).** 21 rule sets were written into temporary Git repositories and the files that Git would add were compared with the files that the old and the new code listed. The old code differed for 12, among them rules anchored to the folder, a rule with a folder inside it, a bare name that is a folder, and a negation.
- **The junction (R5-A-1).** Three tests were written before the fix and failed against the published script. The published script was then run against the junction case: it exited 0 after deleting the files behind the junction and copying the project into that folder.
- **A UTF-16 README (R5-A-2).** The same text was saved as UTF-8 and as UTF-16 and given to the validator: exit 1 and exit 0.
- **Mutations.** 24 mutations of the publish script and 24 of the Python tools were each applied to a copy and run against the tests that were meant to catch them. All were caught. One check, the refusal of a link given with `--scan-file`, could not be exercised here because the account cannot create symbolic links, so a second test stands in for the link detector.

## Found while fixing (not raised by a reviewer)

1. **Weak patterns across the fact list.** An audit of every page and file check showed what each pattern matches and how often. It found the bot-signature entry matching only a heading while the design leans on its conditions (R4-B-1), a matrix row whose column header was not tied to the column, a budget sentence that was not tied to the organization budget, and several other fragments. Each now matches its sentence. A test refuses a claim that gives a reason, such as "so" or "which means", because no pattern can prove one.
2. **unittest reports on standard error.** Separating the streams, as R5-A-6 asks, would have silenced the test summary that the script prints. The script now reads it from standard error.
3. **The stricter path pattern flagged its own test.** A sample path that was not split into pieces in the test file was reported by the scan of that file, which showed that the scan covers the tests too.

## Still open after round 5

These are the spike outputs listed at the end of the round-4 record, and nothing here changed them: the approval window (N11), whether a failed check keeps blocking once the App is suspended, the order for pinning the checks, whether commits made with the GraphQL mutation show as verified, and which permission converts a PR to a draft (all S11), how far spend can exceed `max-ai-credits` with parallel requests and whether the budget stop setting refuses a request (S9), the response of `git/connect` for a missing folder (S4), which item types outbound access protection accepts and whether an Entra subject that follows a repository rename breaks trust (S2), whether suspend and resume need the `write` action (S8), and unattended data agent publishing (S6).
