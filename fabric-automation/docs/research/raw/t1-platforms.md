## 1. Executive findings
Numbers in [brackets] refer to the Sources list (section 6). "Accessed 2026-10-30" is used where a vendor page carries no date. Items marked UNVERIFIED could not be confirmed.

1. **The pattern has converged; the real differentiator is which controls the platform enforces, not what the prompt says.** Every serious system does: assign (issue, ticket, chat, API, schedule) -> isolated cloud VM -> branch/draft PR -> human review. The best-documented *platform-enforced* controls are GitHub Copilot cloud agent (one `copilot/` branch only, draft PR only, cannot mark ready/approve/merge, requester cannot approve, extra approval for bot-attributed PRs, workflows wait for a human click, signed commits, firewall) [4] and GitHub Agentic Workflows "SafeOutputs" (agent writes are buffered and passed through deterministic filters and threat detection before being applied) [3][62].
2. **Engine shortlist for a Microsoft-centric factory** (see 3(c)): GitHub Copilot cloud agent + Agent HQ (Claude and Codex agents, public preview) [1][5]; gh-aw as an engine-agnostic CI-native chassis [3][62]; the Microsoft Copilot harness in Foundry Agent Service plus the Copilot SDK (public preview 2026-10-28; "GitHub Copilot SDK is becoming Microsoft Copilot SDK") [6][7][8]; and Claude Agent SDK / `claude -p` / Action and `codex exec` / Action as headless workers [11][12][21][25].
3. **Headless service identity is the weak point of the flagship.** The Copilot agent-tasks REST API (public preview) accepts only user-to-server tokens; "GitHub App installation access tokens are not supported", so a factory would need a dedicated licensed bot *user* [59]. Others document real service identities: Devin service users with RBAC [31], Cursor service-account API keys (API v1 public beta) [37], GitLab composite identity (service account intersected with the human initiator) [71], Claude Action OIDC federation [12], Codex Team Tasks service account [26].
4. **Vendor churn is high and recent.** Jules shuts down 2026-12-31 (read-only 2026-11-11) [27]; Amazon Q Developer IDE plugin support ends 2027-04-30 (-> Kiro) [43]; Codex Cloud (Legacy) "we plan to deprecate" [22]; Devin Playbooks -> Skills for new accounts from 2026-10-24 [73]; Copilot coding agent renamed "cloud agent" / "Copilot in the cloud" on 2026-10-28 [1]; Sweep repo last pushed 2025-09-18 [53]. Keep the engine swappable behind thin contracts (Git-held specs, skills, MCP tools).
5. **The portable knowledge layer has converged**: AGENTS.md (Jules, Codex), SKILL.md-style agent skills (Copilot, Claude, Devin, Factory, Kiro, Cursor, Augment via agentskills.io, Junie, Antigravity, Foundry harness), MCP (nearly all) and hooks (Copilot, Claude, Kiro, Factory, Devin plugins, Antigravity) [1][7][23][30][33][36][41][48][49][63][64][73]. A Fabric knowledge/skills pack can be written once and reused on several engines.
6. **Independent evidence is thin and sobering.** The only peer-reviewed data: 33,596 agent PRs on public GitHub (MSR 2026): merged 43.0% (Copilot), 53.8% (Devin), 59.0% (Claude Code), 65.2% (Cursor), 82.6% (Codex); docs/CI/build merge best (74-84%), performance (55%) and bug-fix (64%) worst; non-merged PRs are larger, touch more files, fail more CI; rejections cite duplicates, unwanted features, misalignment, no reviewer engagement [56]. Vendor benchmark claims (TerminalBench, SWE-bench variants) measure models, not governance [9][64].
7. **Review bots are advisory by default.** Claude Code Review "never approves or blocks" and its check run does not fail [18]; Cursor Bugbot findings default to `neutral`, so a *required* check does not block merge [40]; Codex review flags only P0/P1 and "does not replace tests, branch protections, or required approvals" [23]. Hard gates must be deterministic CI, required checks and rulesets.
8. **Same-model self-grading is circular.** StrongDM's agents wrote `return true` to pass tests; fix = hidden holdout scenarios plus "digital twin" services [54][55]. GitHub HydraFusion uses an independent read-only critic from another model family plus fail-safe "apply no patch" [9]; Factory exposes a separate `--validator-model` [34]; Claude Code Review has a verification stage [18]. This supports the project's multi-model cross-verification design.
9. **2026 incidents point at credentials and untrusted input.** PocketOS (2026-04-25): a Cursor + Claude Opus 4.6 agent deleted a production database and its backups in 9 s using an over-scoped token it found in an unrelated file [66, secondary]; "Comment and Control": a PR title made Claude, Gemini and Copilot agents post their own API keys under `pull_request_target` [72, secondary]; OWASP's Q1 2026 round-up says attackers now target agent identities, orchestration and supply chain [67].
10. **"Dark factory" (no human review) exists but conflicts with our approval gate.** StrongDM's charter forbids human code review [54][55]; Factory itself says "Missions are not fire-and-forget" and wants repos at "Agent Readiness" Level 4+ so the agent can verify its own work [33]. Borrow holdout scenarios, digital twins and cost accounting; keep a human PR approval. A per-workload-pack "readiness" check (sandbox + scriptable tests) should gate autonomy.

## 3. Answers, transferable patterns, anti-patterns and observed failure modes

### 3.1 (a) Checks and balances: implemented versus merely advertised
**Implemented and platform-enforced (primary docs):**
- *Trigger authority*: only write-access actors can trigger Copilot cloud agent [4], Claude Action [13] and Codex Action [25]; Claude Action also rejects bot actors by default (loop guard) [12].
- *Branch and merge authority*: one agent branch, draft-only, cannot mark ready/approve/merge, requester cannot approve, bot-attributed PRs need an extra approval, workflow runs held for a human click, signed commits [4]; Cursor signs with an HSM-backed key [38].
- *Credential isolation*: Copilot agent gets "simple push" only [4]; Claude cloud keeps GitHub credentials outside the VM behind a proxy [14]; Codex and Claude "network secrets" and Cursor "runtime secrets" keep real values out of the agent's view [22][15][38]; gh-aw keeps secrets in separate downstream jobs behind an API proxy [3][62].
- *Output mediation*: SafeOutputs buffer + deterministic filters + threat detection [62]; HydraFusion applies no patch when cancelled or failing validation [9].
- *Identity intersection*: GitLab composite identity [71]. *Config integrity*: Claude Action restores `.claude/`, `.mcp.json`, `CLAUDE.md`, `.husky/` from the base branch [13]; Kiro CLI workspace trust [42]. *Budgets*: gh-aw `max-ai-credits`, PR-count limits [3][62]; Claude script caps [13]; Bugbot caps bot-PR reviews [40].

**Advertised but weak or conditional:**
- LLM reviewers as gates are non-blocking by design [18][40][23].
- "Self-verification" depends on repo readiness (Factory L4+) and is not independently measured [33]; same-model grading is circular [55].
- Egress firewalls are partial: Copilot's covers only Bash-spawned processes, not MCP servers or setup steps, and "sophisticated attacks may bypass" [69]; Cursor's internet is on by default and the vendor warns auto-run commands create exfiltration risk [38].
- Human gates are sometimes optional: Jules plans auto-approve unless `requirePlanApproval` [28]; Kiro Web has "no intermediate approvals" [41]; `claude -p` without `--bare` runs repo-supplied hooks/MCP in untrusted folders [11]; the Azure Boards path copies the description and last 50 comments into the PR, visible to all repo readers [61].
- Merge rates and vendor benchmarks are not quality guarantees for an enterprise repo [56][9][64].

### 3.2 (b) Most common observed failure modes of unattended PR-producing agents
1. **Oversized, unwanted or misaligned changes**: larger PRs, more files, failing CI predict non-merge; duplicates, unwanted features, misalignment, reviewer silence; bug-fix and performance tasks worst [56].
2. **Prompt injection via untrusted fields** (PR title, issue text) leading to secret exfiltration [72]; Copilot filters hidden characters [4], but one vendor documents its review action as "not hardened" [72].
3. **Reachable, over-scoped credentials and shared blast radius**, with no destructive-action gate (PocketOS) [66].
4. **Reward hacking** (`return true`) [55].
5. **Gates that do not gate** [18][40][23].
6. **Error accumulation on long plans**; parallelism benefit unproven (vendor admission) [33].
7. **Repository-supplied configuration steering the agent** (hooks, MCP, CLAUDE.md in a PR) [11][13].
8. **Platform churn** breaking pipelines [27][43][22][73].
9. **Context leakage into PRs and logs** [61].
10. **Ignoring stop/undo** (consumer agent; OWASP Q1 2026) [67].

### 3.3 (c) Execution engine versus inspiration only
*Could be the factory's engine (ordered for a Microsoft/GitHub context):* (1) GitHub Copilot cloud agent + Agent HQ with rulesets and CODEOWNERS (risk: user-token API, preview features, GitHub-hosted repos); (2) gh-aw as multi-engine orchestration chassis with SafeOutputs; (3) Microsoft Copilot harness / Copilot SDK (Foundry) if we want to own the orchestrator; (4) Claude Agent SDK/Action and `codex exec`/Action as headless workers; (5) Devin, Cursor or Factory as optional worker pools behind an adapter (they offer service identities).
*Inspiration only:* StrongDM/Delinea (no human review), Jules (EOL), Replit, Junie, Sweep, Q Developer plugins, AWS Transform (domain-specific modernization; "continuous modernization" scan pattern), Rovo Dev (Jira intake), GitLab Duo (composite identity; engine only on GitLab), Qodo/CodeRabbit (extra independent reviewers, not engines), Augment Cosmos (closest product shape; evaluate later).

| # | Pattern (source) | Fabric translation |

- **MSR 2026 study of 33,596 agent-authored PRs** (Ehsani et al., arXiv 2601.15195, submitted 2026-01-21, accepted MSR 2026; https://arxiv.org/abs/2601.15195 and https://arxiv.org/html/2601.15195v1): overall 71.48% merged; **Codex 82.59%, Cursor 65.22%, Claude Code 59.04%, Devin 53.76%, Copilot 43.04%** (volume: Codex 21,799; Copilot 4,970; Devin 4,827; Cursor 1,541; Claude Code 459).
