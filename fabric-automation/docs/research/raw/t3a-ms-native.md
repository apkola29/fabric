Run date: 2026-10-30 · Thread owner: T3a · Final: sections 1-7 complete; Appendix A = raw evidence log. Body (sections 1-6) is longer than the ~2,500-word target because the requester added a per-item-type coverage matrix and an MCP-coverage column.

## 1. Executive findings (max 10 bullets, most decision-relevant first)

All facts verified 2026-10-30 unless marked UNVERIFIED. "Learn date" = page metadata `ms.date / updated_at`.

1. **There is no Microsoft-native autonomous code factory; there is a toolbox.** Official parts: knowledge (`microsoft/skills-for-fabric` v0.3.20, 2026-10-29: 25 skills, plugins `fabric-skills` + `powerbi-authoring`, MIT), live access (14 Fabric/Power BI MCP servers listed on Learn 2026-10-21), executors (`fab` 1.8.0, `fabric-cicd` 1.4.0, `fntk` alpha, `powerbi-report-author`) and in-product agents (Copilot, ontology agent, Project Osmos). Learn: skills are "static knowledge. They don't execute code on their own." Orchestration, isolation, gates and approvals must be built.
2. **Maturity is low and uneven.** Only 1 of 26 shipped skills declares maturity (`git-integration-operations-cli`: `experimental`). Preview/alpha: Osmos, notebook toolkit (0.0.1a12), data-agent SDK (0.1.33a0), data-agent ALM and evaluation, DW MCP, RTI MCP, hosted Power BI Authoring MCP, all ontology features. GA: FabricIQ MCP, local Power BI Authoring MCP, Data Factory and Power BI Copilot. Skills ship roughly weekly with breaking renames: pin commit SHAs, never auto-update.
3. **Unattended identity is the binding constraint.** SPN/MI-capable: `fab`, `fabric-cicd`, local Power BI Authoring MCP, local Fabric MCP (Docker SPN), data-agent SDK, Execute DAX Queries REST, Git integration (SPN needs workspace Admin and a configured connection). User-only: FabricIQ MCP ("Service-principal and application-only authentication aren't supported"), hosted Core MCP (browser OAuth), hosted Authoring MCP, DW MCP, ontology MCP (known issue), Osmos (`az login`), every Copilot feature. Data-agent SPN support is contradicted inside Learn (see section 6).
4. **Data agents: file-defined but no official skill.** Definition = `Files/Config/{data_agent.json, draft|published/stage_config.json, <type>-<name>/datasource.json + fewshots.json}` with public JSON schemas; Git/deployment pipelines work (preview); the only Microsoft test harness is `evaluate_data_agent` (preview, notebook-hosted, LLM-judged, needs a published agent). The factory must build the data-agent workpack.
5. **Ontology skill is stale against the platform.** `fabriciq-ontology-cli` authors the old `EntityTypes/*/definition.json` format (zero TMDL references in the installed skill); Learn documents a new TMDL-based format and says the old experience "retires on Jan 31, 2027". Ontology is preview throughout.
6. **Semantic models are best covered; BPA is not deterministic in the skill.** `semantic-model-authoring` prefers the Power BI Authoring MCP (local GA: SPN, `--readonly`, transactions, DAX), but its "Analyze Best Practices" is an LLM review against markdown guidelines. Microsoft publishes deterministic BPA rules (`microsoft/Analysis-Services` `BPARules.json`) plus a CI sample that runs them with Tabular Editor 2 (third-party engine).
7. **Reports have a real render gate.** `powerbi-report-cli` v1.0.5 + `powerbi-report-author` CLI: PBIR `validate`, `scaffold`, `pack/unpack`, and `preview --host service --headless --screenshot` (no Desktop needed). Desktop Bridge is Windows-only, local named pipe. Learn's Skills overview still claims skills "don't currently render finished Power BI reports": stale. Distribution channel of `powerbi-report-author` is UNVERIFIED (not on the npm feed queried).
8. **Largest gaps (no owning skill):** data agents; greenfield Data Factory pipelines, copy jobs, Airflow, dbt; Spark job definitions; environments; ML; graph; maps; paginated reports; user data functions; KQL querysets/dashboards; plus nothing for `fabric-cicd`, testing, or evaluation. No MCP server covers Git integration, deployment pipelines, Spark/notebook runs, or report rendering (REST/`fab` needed).
9. **Copilot in Fabric/Power BI is interactive assist, not an automation surface** (release table: notebook, DW = preview; Data Factory, Power BI, RTI = GA; no API/SPN) -> Avoid in the factory. Osmos is a preview remote worker for Lakehouse/Spark outcomes with an undocumented task API -> optional workload pack behind a flag, never a dependency.
10. **Safety:** Microsoft's own MCP docs warn that autonomous clients "might perform destructive actions" and that blocking flags "aren't standardized"; hosted Core MCP exposes irreversible `delete_workspace`. Skills carry mandatory telemetry headers (`x-ms-fabric-skill`) and interactive `ask_user` approval gates. The factory needs tool allow-lists, a least-privilege SPN, isolated workspaces and a non-interactive policy layer.

## 3. Transferable patterns, anti-patterns and observed failure modes

**Patterns worth copying (all evidenced):**
- **Intent-routed modes with a hard read-only tier.** `dataflows-cli`, `fabriciq-ontology-cli`, `eventhouse-cli`: "consumption is read-only"; "a previewed definition tree is not a saved one"; writes only through authoring mode (skills SKILL.md, read 2026-10-30).
- **Plan, locked spec, approval, act.** `powerbi-report-cli` stops greenfield build-and-publish "at the locked-spec approval barrier" (CHANGELOG 0.3.19); ontology agent Plan mode (default, read-only) vs Act mode (Learn 2026-10-21); SRE Agent Review (default) vs Autonomous per response plan, "start with review mode ... two to four weeks" (Learn run-modes 2026-06-11). Maps directly to intake spec -> branch -> human PR approval.
- **MCP-first tool tiers with fallbacks.** `semantic-model-authoring`: Tier 1 Power BI Authoring MCP, Tier 2 TMDL / `az rest getDefinition -> edit -> updateDefinition`; anti-pattern = reading stale on-disk TMDL while MCP is connected.
- **Draft vs published separation and one writer per branch.** Data agent: edit `draft/` only, never `published/` (Learn 2026-08-31); git skill: "pick one writer per branch", read `git/status` and pass `workspaceHead` to every commit/update.
- **Pin tool contracts.** FabricIQ `X-Variants` header; `powerbi-report-author scaffold --offline` pins `$schema` versions; Authoring MCP `@latest` should be version-pinned (inference).
- **Ephemeral-tenant behavioural tests (a pattern to build, not found in the public repo).** A dynamic workspace per run, service-principal login, a per-test timeout, and a flaky-test registry with issue links.
- **Evidence-quoting.** Osmos skill: report counts as literal `count()` output, poll messages not just status, never invent data when a query returns no rows (ontology agent).

**Anti-patterns and failure modes actually observed:**
- **Breaking churn.** 0.3.17 merged four report skills into `powerbi-report-cli` ("a rename as well as a merge"), moved the FabricIQ endpoint and replaced `ResolveReportIdFromUrl`; 0.3.20 renamed `onelake-catalog-govern-cli`; Learn's discover page still cites removed `eventhouse-consumption-cli`/`sqldw-authoring-cli` (CHANGELOG; Learn 2026-09-09).

FabricIQ doc: a configured `Authorization` header disables interactive OAuth.
- **Drift between skills, MCP config and Learn.** Ontology skill vs TMDL format; skill config tool `execute_query` vs Learn `executeSQL` (DW MCP); data agent GA (concept page) vs preview (release table) vs "GA" (deployment-pipelines skill table) vs ALM "preview"; skills overview claims no report rendering.
- **Interactive gates in skills.** `ask_user` confirmations and approval "in a later reply" stall a silent run unless the intake spec pre-answers them.
- **Black-box worker vs decomposition.** Osmos skill: hand off the full scope as ONE task, "do not decompose" (instruction cap 9,500 characters), the opposite of a factory that splits work.
- **Non-deterministic judges.** LLM best-practice review and LLM-judged data-agent evaluation (`critic_prompt`) cannot be sole merge gates.
- **Egress and telemetry.** Skills require `x-ms-fabric-skill` headers; MCP docs: schemas, metadata and query results flow to the LLM provider; unattended Authoring MCP needs an explicit EULA flag.
