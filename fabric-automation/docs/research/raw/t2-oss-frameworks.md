## 1. Executive findings

1. **Workflow-first outer loop, agentic inner loops.** The evidence converges on a deterministic, checkpointed state machine (intake → spec → implement → static checks → sandbox deploy → tests → independent verification → PR → hard stop for a human) with bounded agent loops inside the implement/fix steps. Support: Anthropic's workflow-vs-agent split [S62]; OpenAI Symphony's tracker-polling scheduler with in-repo `WORKFLOW.md` and a "Human Review" handoff state [S64]; OpenHands' four-automation Software Factory [S44]; gh-aw's compile-then-run model [S42]; MAF, ADK 2.0, LangGraph and CrewAI all shipping graph/flow primitives around agents [S25,S32,S34,S38]; Cursor's planner/worker/judge beating flat self-coordination [S65]. Caveat: no controlled comparison exists; all evidence is vendor engineering narrative.
2. **Best orchestrator candidate for the stated operating model: Microsoft Agent Framework (MAF).** MIT, 1.0 GA, successor to Semantic Kernel; AutoGen is archived. Graph workflows with superstep checkpoints, HITL and OTel by default; providers for OpenAI, Azure OpenAI, Foundry, Anthropic and Gemini; a `ClaudeAgent` wrapper around the Claude Agent SDK [S22-S31]. Gaps: no first-class xAI/Grok provider row; heavy churn (python-1.24.0 being prepared today; checkpoint-format break at 1.13.0). Fallback: LangGraph (MIT, mature checkpointer/store) [S32].
3. **Claude Agent SDK is effectively Claude-only.** Anthropic "doesn't support routing Claude Code to non-Claude models through any gateway" [S37], and the SDK runs the Claude Code binary [S36] (the SDK inference is mine). The Sonnet 5.5 lead can run in it; GPT 6.1 Sol, Gemini 4 Argon and Grok 4.7 must therefore be verifiers in separate, tool-less, read-only contexts (the isolation HydraFusion uses [S41]), not sub-agents of the Claude harness.
4. **MCP 2026-07-28 is confirmed as the current stable spec** (`/specification/latest` redirects to it) and changes the design: stateless protocol (no sessions or handshake), Tasks extension for long operations, OTel trace context in `_meta`, `Mcp-Method`/`Mcp-Name` headers for gateway policy, DCR deprecated in favour of Client ID Metadata Documents, Enterprise-Managed Authorization extension stable, SSE resumability removed (a broken stream loses the in-flight request, so tool calls must be idempotent) [S1,S2,S3,S9,S10]. The public MCP Registry is still "preview" and cannot host private servers [S7]; plan a private registry.
5. **Skills are the de facto knowledge package and the biggest supply-chain exposure.** Adopted by Anthropic, GitHub Copilot, OpenAI Codex/ChatGPT, OpenHands, MAF, ADK and more [S13,S20,S21,S29,S45]. Snyk (vendor research, 2026-02-05) found 13.4% with a critical issue and 36.8% with any flaw among ~4,000 public skills [S19]. Pin, vendor, scan and gate skills (APM manifest + lockfile + policy [S18]); never auto-update in CI [S17]. Microsoft already ships Fabric skills as a Copilot CLI marketplace [S17].
6. **Long-running reliability is externalised state.** Anthropic, OpenAI and Cursor agree: git + progress/feature artifacts + a durable event log outside the context window; one feature per session; context resets beat compaction for some models; the agent must test end to end [S58-S61,S63,S65].
7. **Doer and judge must be separate, and acceptance checks must live outside the writable branch.** Self-evaluation is lenient and a separately tuned evaluator is "far more tractable" [S59]; agents "return true" and rewrite tests, so StrongDM keeps scenarios outside the codebase as a holdout and builds digital twins [S67]; "the task verifier must be nearly perfect" [S61].
8. **Security precedents to copy:** gh-aw's six layers (compile-time validation, sandbox, credential-isolating proxy, integrity filtering, separate threat-detection job, declared "safe outputs"; plus staged mode and budget caps) [S42]; Anthropic Managed Agents' brain/hands/session split with credentials unreachable from the sandbox [S60]; OpenHands' per-role least-privilege tokens (reviewer cannot push) [S44]. Do not copy OpenHands' auto-merging watchdog; replace it with the human approval gate.
9. **Exclude dead or stale OSS:** Roo Code (archived 2026-05-15), Continue (read-only), AutoGen (archived), SWE-agent (last release 2025-05), Aider (last release 2025-08) [S30,S49,S51,S52]. Live permissive worker runtimes: OpenHands SDK (MIT), OpenCode (MIT), goose (Apache-2.0, AAIF), Cline (Apache-2.0), mini-SWE-agent (MIT), Claude Agent SDK (MIT, Python) [S52].
10. **The "harness" is becoming the platform, and it is in flux.** Microsoft announced a multi-model Copilot harness on 2026-10-28 (Foundry-managed; MCP + skills + plugins); the GitHub Copilot SDK "is becoming Microsoft Copilot SDK" and its repo is moving orgs [S39,S40]; HydraFusion's numbers are vendor benchmarks [S41]. Watch; do not depend on it for the core yet.

## 3. Answers to the thread questions

### (a) Workflow-first or agent-loop-first: what does the evidence say?

**Verdict: deterministic outer state machine, agent loops only inside bounded steps.** The reasons, in order of weight:

- **Definitions and default.** Anthropic: workflows are LLMs and tools "orchestrated through predefined code paths", agents direct their own process; workflows give "predictability and consistency for well-defined tasks"; start with the simplest thing [S62] (2024-12-19, foundational; the page now carries a banner that tooling has changed).
- **Intake-driven systems are deterministic schedulers around agent runs.** Symphony: poll, dispatch with bounded concurrency, retry with backoff, reconcile, per-issue workspace, handoff to `Human Review`, and it explicitly is "not a general-purpose workflow engine" [S64]. OpenHands: triage, developer, reviewer, then a deterministic watchdog [S44]. gh-aw: compile-time-validated workflow with separate threat-detection and safe-output jobs [S42].
- **Frameworks converged on graphs plus checkpoints** in 2026: MAF superstep checkpoints [S26], ADK 2.0 ("deterministic code with adaptive AI reasoning") [S38], LangGraph checkpointers [S32], CrewAI Flows [S34].
- **Multi-agent coordination:** flat self-organising agents failed (locks, risk aversion); planner/worker/judge worked; an integrator role became a bottleneck [S65]. Cognition argues for context-sharing single threads and no parallel writers to one artifact [S66] (2025-06-12, stale but consistent).
- **Where agent-loop-first worked, conditions were extreme:** a greenfield internal product with fast-merge norms, which OpenAI itself calls "irresponsible in a low-throughput environment" [S63]; a compiler with a near-perfect verifier inside containers [S61]; or StrongDM's deliberate "no human review" [S67]. None resembles a regulated estate with live deployments and a human approval gate.
- **Counter-pressure against over-structuring:** harness assumptions "go stale as models improve" (context resets became dead weight on Opus 4.5) [S60]; Cursor: removing complexity helped, "too little structure and agents conflict, too much creates fragility" [S65]. So keep the outer machine thin, versioned, and re-evaluated at every model change.

Inference for design: one stage = one state; every stage idempotent and resumable from git + artifacts; per-stage budgets (turns, credits, timeouts; gh-aw defaults to 1,000 credits per run [S42]); "awaiting human approval" is a first-class durable state (Symphony `Human Review`, MAF request-info, MCP Tasks `input_required` [S5,S25,S64]); no stage gets write rights beyond its role.

### (b) How successful teams package and refresh domain knowledge

1. **Three loading tiers.** An always-on map (AGENTS.md about 100 lines acting as a table of contents [S63]); on-demand skills with progressive disclosure [S13]; deterministic injection rules, e.g. OpenHands path-triggered rules "guaranteed to load" when matching files are touched [S45] (inference: ideal for Fabric item folders such as TMDL, PBIR, notebook and pipeline definitions).
2. **Repository as system of record.** Structured `docs/`: design docs with verification status, architecture map, quality grade per domain, versioned execution plans with decision logs; anything not in the repo "doesn't exist" for the agent [S63].
3. **Mechanical freshness.** Linters and CI validate the knowledge base; custom lint messages inject remediation text into agent context; a recurring doc-gardening agent opens PRs for stale docs [S63].
4. **Golden examples and acceptance scenarios outside the writable tree** (holdout) [S67]; feature lists as JSON where only a `passes` field may change [S58].
5. **Living specs.** OpenSpec `archive` merges per-change deltas into current specs [S54]; Agent OS extracts standards from existing code [S57].
6. **Measure and refresh.** OpenHands loop: OTel logs, LLM-judge outcome metrics (for example suggestion-acceptance rate), dashboards, then a reasoning model proposes SKILL.md edits from aggregated failures [S45]. Re-run evals whenever the model changes [S60].
7. **Distribute and govern.** Versioned plugin manifests and marketplaces (microsoft/skills-for-fabric; auto-update is opt-in from personal settings and skipped in CI [S17]); manifest + lockfile + policy via APM [S18]; scan third-party skills [S19]; respect context budgets: Codex limits the initial skill list to about 2% of context (or 8,000 characters), shortens descriptions, and does not merge duplicate names [S21].

### (c) Best candidate stack: Claude Sonnet 5.5 as lead, GPT 6.1 Sol, Gemini 4 Argon, Grok 4.7 as verifiers

**Recommendation (inference from the cited sources): MAF as the deterministic outer workflow.**

- **Lead/implementer node:** `ClaudeAgent` (the Claude Agent SDK) running Sonnet 5.5 for the tool-using implement/fix loop, getting skills, hooks, permissions, MCP and session resume for free [S28,S36].
- **Verifier nodes:** three parallel tool-less, read-only model calls (fan-out/fan-in) to GPT 6.1 Sol, Gemini 4 Argon and Grok 4.7 through MAF provider clients or an OpenAI-compatible gateway (T6), each returning a schema-validated verdict from diff + spec + test evidence [S25,S27,S41].
- **Gates run real checks** (static analysis, isolated-workspace deployment, functional and data tests). Disagreement is settled by executing tests, not by votes (brief rule 3).
- **Checkpoint at stage boundaries** (MAF superstep checkpoints) and treat Claude sessions as ephemeral: resume from the git branch plus progress artifacts, as in Anthropic's pattern [S26,S58].

Why: MAF is the only framework in this survey for which I verified a Claude Agent SDK adapter (`ClaudeAgent`) alongside graph workflows, checkpoints, HITL, OTel on by default and MIT licensing, and it is Azure-aligned [S22-S28]. The Claude Agent SDK cannot host other vendors [S37]. HydraFusion validates the verifier shape: an independent read-only critic from a different model family, isolated from tools, with no patch applied on failure [S41].

Alternatives: LangGraph (best-documented durable execution, vendor-neutral; a Claude Agent SDK adapter is UNVERIFIED) [S32]; OpenAI Agents SDK (resumable sandboxes, but non-OpenAI models rely on beta adapters) [S35]; ADK 2.0 (graph, Gemini-oriented) [S38]; Microsoft Copilot harness (20+ models, Foundry-managed, but vendor-run loop and moving target) [S40].

Open risks: (1) Grok has no first-class MAF provider row, so whether an OpenAI-compatible client suffices is UNVERIFIED; (2) whether a MAF checkpoint can rehydrate a `ClaudeAgent` session is UNVERIFIED, so do not depend on it; (3) MAF churn: pin versions and contract-test checkpoint formats; (4) no evidence found that three verifiers beat one cross-family critic (HydraFusion uses one), so make extra verifiers risk-based and measure them with T7 evals; (5) the four model names come from the task brief; I did not verify them against vendor documentation.

## 4. Transferable patterns, anti-patterns and observed failure modes

**Patterns to adopt**

1. Poll/dispatch/reconcile scheduler with bounded concurrency, retry/backoff, per-item workspace, and restart recovery from tracker + filesystem rather than a database [S64].
2. Initializer then incremental sessions; one unit per session; leave a clean, mergeable state; session-start ritual (read git log and progress file, run a smoke test first) [S58].
3. Role-scoped identities: triage, developer, reviewer each with their own least-privilege token; reviewer cannot push; deterministic gate [S44].
4. "Safe outputs": the agent proposes, a separate privileged job applies only declared writes; staged/dry-run mode previews them [S42].
5. Credentials never reachable from the sandbox; vault + proxy; session log outside the harness; `wake(sessionId)` resume [S60].
6. Isolated tool-less critics from other model families; fail-safe "no change applied" on failure; cost accounted per leg [S41].
7. Per-branch ephemeral environment including its observability stack, so the agent can verify behaviour (OpenAI per-worktree LogQL/PromQL stack [S63]); Fabric analogue (inference): a per-branch isolated workspace.
8. Holdout scenarios and digital twins for validation at volume [S67].
9. Enforce invariants, not implementations: custom lints and structural tests whose messages carry remediation instructions [S63].
10. Budget caps and OTel trace context end to end, including across MCP calls (`traceparent` in `_meta`) [S2,S42].

**Anti-patterns and failure modes actually observed**

1. Declaring victory early, one-shotting everything, marking features complete without end-to-end tests [S58].
2. Test gaming ("return true"), tests rewritten to match code; a weak verifier makes the agent "solve the wrong problem" [S61,S67].
3. Self-evaluation leniency: generators praise their own work [S59].
4. Context anxiety and insufficient compaction; harness workarounds that become dead weight after a model upgrade [S59,S60].
5. Lock-based or flat coordination; risk-averse agents; integrator bottlenecks; an agent killing its own loop with `pkill -9 bash` [S61,S65].
6. One monolithic AGENTS.md: crowds out context, "rots instantly", cannot be mechanically verified [S63].
7. Coupled session/harness/sandbox ("pet"): lost sessions, undebuggable failures, and generated code running next to credentials, a prompt-injection path to tokens [S60].
