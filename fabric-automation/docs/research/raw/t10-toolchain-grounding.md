## 4. Power BI Authoring (local): flags and license

From https://github.com/microsoft/powerbi-modeling-mcp (README, **checked**): `--start` (required), `--readonly` (safe mode, no writes), `--readwrite` (the default; a confirmation prompt before an edit is applied to the semantic model, once per database), `--compatibility`, `--authmode interactive|serviceprincipal`, `--accepteula`. ## 8. The MCP protocol moved (**checked**)

Revision 2026-07-28 of the protocol (https://modelcontextprotocol.io/specification/2026-07-28/basic/versioning.md ) is stateless: the `initialize` handshake, the `initialized` notification and the `Mcp-Session-Id` header are not part of it. Every request carries per-request metadata, HTTP requests carry `MCP-Protocol-Version`, `Mcp-Method` and `Mcp-Name` headers, and `server/discover` is the optional discovery call. The versions up to `2025-11-25` are "legacy". A dual-era client probes and falls back to `initialize`; a legacy client talking to a modern-only server fails, and the modern server should name its supported versions in the error. The servers read for this note answer both eras: the Fabric local server (1.5.0 and 1.6.0) and the Azure server (3.0.51) answer a `server/discover` call with a modern reply and an `initialize` call with the legacy handshake (a probe of 2026-10-31; before that, with the legacy handshake alone, they had looked legacy-only). A server that settles its era on its first request refuses the other era afterwards, so a probe that gives up on a silent `discover` has to start a new process before it tries `initialize`. The wait matters: the local Fabric server (1.5.0) took 4.6 seconds to answer `discover` on a loaded Windows machine (about 3 seconds on a quiet one), and a probe that waited 5 seconds recorded it as legacy in three runs out of four and as modern in the fourth, so the probe waits 20 seconds. A tool contract capture therefore has to speak both eras.

## 9. Statements that limit use

- Fabric IQ: "Fabric IQ MCP supports read-only consumption scenarios. It doesn't provide workspace administration, development, or item-creation functionality."
- Power BI Authoring: "The Power BI Authoring MCP server can only execute modeling operations. It cannot modify other types of Power BI metadata, such as report pages or semantic model elements like diagram layouts." The Learn page (https://learn.microsoft.com/en-us/power-bi/developer/mcp/power-bi-authoring-mcp , **checked** on 2026-10-31) adds: "DAX query execution tools have a hard limit of 100,000 rows." The first cold check of this note said that the figure is not on the current page; a second reviewer found it there, and reading the page settled it: it is there, and the README does not repeat it.
- Real-Time Intelligence: "This MCP server is not intended to be exposed directly as a production HTTP endpoint."
- Data agent as an MCP server: responses "might be sent outside of Fabric's compliance boundary or geographic region".
- SQL MCP Server: "intentionally doesn't support NL2SQL".

## 10. Surprises and conflicts

1. The skills repository has two marketplace files that do not say the same thing. Only `.github/plugin/marketplace.json` lists `execute_query` as the tool of the SQL endpoint server; `.claude-plugin/marketplace.json`, which `copilot plugin marketplace add` reads, has no tool list. The Learn page names `executeSQL`.
2. Release v0.3.20 renamed a skill. A profile that names a skill breaks on update unless the gap analysis catches it.
3. Both Fabric plugins define a server under the same name for different servers.
4. Learn still describes retired persona bundles and a `--filter` switch; the current README says a bundle installs whole.
5. The container image `latest` is stale; npm `@latest` is what every example uses.
6. The Azure MCP Server's `latest` on npm is a beta (`4.0.0-beta.4`) while a stable `3.0.0` also exists, and its README on the main branch still announces "2.0 is now generally available". The kit pins an exact version either way.
7. The Power BI authoring server blocks every tool until its license is accepted; unattended acceptance is a flag that the operator sets after reading it.
8. The corporate-feed `EALLOWREMOTE` failure on npm, and TLS failures to the npm and NuGet registries on one network, mean that a lock refresh belongs on a hosted runner.
9. The MCP blocks bundled in `fabric-skills` use a header helper that puts an `az account get-access-token` token into `Authorization`, while the Fabric IQ page says that a configured Authorization header overrides the interactive sign-in. The kit does not copy those blocks.
10. The data agent MCP documentation still requires an `initialize` handshake (and rejects dynamic client registration), and the SQL MCP Server documents the protocol version `2025-06-18` as its fixed default. A client that speaks only the 2026-07-28 revision fails against both, so the kit's probe asks `server/discover` first and falls back to the legacy handshake.
11. The container registry also carries floating tags `1.6-amd64` and `1.6-arm64`, has no `1.5.0` image, and `latest` is the 1.4.0 image rather than a moving alias.

## 11. UNVERIFIED

The status of the hosted core and SQL endpoint servers; whether the hosted servers accept a service principal (only Fabric IQ says no, and the ontology page names a known issue); the npm publish timestamps; whether Copilot CLI honors `enabledPlugins` from `.github/copilot/settings.json` (documented, not run); a recipe to pin a marketplace plugin by commit for Copilot CLI (VS Code accepts `owner/repo#<40-character commit>` for a marketplace; for Copilot CLI a `#ref` on the marketplace source is documented, a commit pin was not tried); the offline behavior of the Bicep server; the streamable-HTTP behavior of several hosted servers marked "H" in the directory.
