## 1. Executive findings
1. **No data-platform vendor ships a fully autonomous, silent intake-to-validated-PR loop for data; each keeps a human at the run/approve step.** Google's agent "cannot execute pipelines" [S37]; dbt Wizard and Snowflake CoCo default to ask/confirm [S28][S17]; Databricks defaults to classifier auto-approve [S4]. The nearest full loop is generic: Kiro Web (spec, isolated sandbox, PR, scheduled tasks) [S40]; dbt Wizard already opens PRs labelled agent-made [S27].
2. **An LLM approver is not a security control.** Databricks says auto-approve "is not a security boundary" yet makes it the default and the only mode for scheduled runs, which use the creator's permissions [S4][S5]. Snowflake's system-owned, fail-closed managed settings (force sandbox, disable bypass) are the stronger pattern [S18]. Use a dedicated least-privilege identity and deterministic policy outside the model.
3. **Copy the dbt + Snowflake verification stack**: unit tests, contracts that fail the build, Slim CI (state + defer), PR-comment data diff of keys/rows/columns [S31][S34], per-PR zero-copy clone databases [S19], and downstream-BI impact CI (Looker CI after dbt CI) [S39].
4. **Test-data cost is platform-specific.** Copy-on-write clones (Snowflake, BigQuery) are the benchmark [S23][S38]; Databricks shallow clone excludes streaming tables and MVs [S13]; Lakebase branching is Postgres-only [S14]. Fabric's equivalent needs explicit design (T4).
5. **Curated semantics plus an evaluation set drive accuracy.** dbt (2026-04-07, vendor-run, 11 questions): Semantic Layer 98.2-100% vs text-to-SQL 84.1-90.0%, about 50% on raw schema [S33]; Snowflake scores agents per step against ground truth (GPA) [S21]; Databricks uses benchmarks and a curated knowledge store [S8].
6. **Independent evidence is thin.** Platform agents have only vendor-run numbers or quotes. Academic ELT-Bench-Verified (2026-03-31): extraction/loading 37% to 96%, transformation 22.66%, and 82.7% of failed tasks had benchmark-attributable errors (ambiguous specs, rigid checkers) [S45]. Executable acceptance criteria and tests of the tests are first-class needs.
7. **Knowledge packaging converged on open standards**: Agent Skills (Databricks, Snowflake, dbt), AGENTS.md (Snowflake, SageMaker), MCP (all), A2A (Google), ACP (Snowflake) [S7][S16][S30][S37][S43]; org-level skills carry rules such as PII masking [S7].
8. **Names churn; design to standards.** Assistant to Genie Code, Spaces to Genie Agents, Asset Bundles to Declarative Automation Bundles, Cortex Code to CoCo, dbt Copilot to Wizard, Fusion to dbt v2 (GA Oct 2026, verified in dbt release notes), Q Developer IDE to Kiro (EOL 2027-04-30); Fivetran and dbt Labs merged 2026-06-01 [S1][S8][S11][S16][S26][S27][S41][S35].
9. **Usage billing has started** (Databricks 2026-07-08; dbt 2026-09-01); unattended agents need budgets [S1][S26].
10. **Data-specific gates are mostly not native.** Only dbt Advanced CI (Enterprise tier) gives a deterministic baseline data diff [S31]; no vendor read documents automated idempotency, cost-regression or PII gates for agent output (inference). Plan to build or buy (T3c).

## 3. Answers to the three cross-cutting questions
### (a) Data-specific quality gates that are standard practice
| Gate | Standard at these vendors? | Evidence |
|---|---|---|
| Schema and contract checks | **Yes** | dbt contracts fail the build [S34]; Lakeflow expectations warn/drop/fail [S15]; Dataform assertions [S38]; Snowflake data metric functions [S24] |
| Row-count / aggregate reconciliation | **Partial** | Genie Code "highlights unexpected changes in row counts or schemas" (an LLM reading, not a gate) [S3]; deterministic version is dbt compare [S31] |
| Data diff against baseline | **Only dbt Advanced CI** (Enterprise/Enterprise+; BigQuery, Databricks, Postgres, Redshift, Snowflake) | PK/row/column changes in the run and as a PR comment; `event_time` limits compare to the overlapping window [S31]. No native equivalent found at Databricks, Snowflake, Google, AWS |
| Idempotency and backfill safety | **Partial** | dbt microbatch batches by `event_time` [S34]; dbt State rebuilds a model that failed a test rather than reusing it [S32]; Databricks offers dry-run/full-refresh [S3]. No vendor documents an automated idempotency check on agent output (inference) |
| Cost and performance regression | **Partial** | Genie Code diagnoses full-recompute vs incremental MVs [S3]; Google agent optimises (partitioning) [S37]; Slim CI/State cut compute [S19][S32]. No PR-level cost gate documented (inference) |
| Lineage and impact analysis | **Yes** | dbt MCP `get_lineage`, `get_model_health` [S29]; Unity Catalog lineage in Genie Code [S2]; Looker CI downstream Explores, lineage GA [S39]; Knowledge Catalog [S37] |
| PII checks | **Partial** | Workspace skill example "masks sensitive columns" [S7]; Google auto-encrypts PII-flagged columns [S36]; Snowflake PII tooling not verified |

### (b) Cheap and safe non-production environments
- **Snowflake**: per-PR zero-copy clone database with Slim CI importing prod state; dev vs prod databases; OIDC/PAT for the runner; read-only role against prod [S19][S17][S23].
- **BigQuery**: table clone, writable, billed only for changed data; intended for "development and testing" [S38].
- **Databricks**: shallow clone (metadata only) but not for streaming tables or MVs [S13]; bundle development target prefixes resources and pauses schedules [S11]; Lakebase branches are Postgres-only [S14]; synthetic-data skill [S12].
- **dbt**: dev schema + `defer` to prod + `state:modified+` (Slim CI), or `dbt clone`; unit tests use static mock inputs [S34].
- **Looker / AWS**: Looker CI validates before merge [S39]; Kiro gives a per-session code sandbox, but no data clone or branch is documented [S40][S43].
- **Sampled data**: only used as agent context (BigQuery sample rows, profiles) [S37] or as a bounded compare window [S31]. No vendor documents production-sampled test sets for agents (UNVERIFIED).

### (c) Observed failure modes of AI-generated pipelines and transformations
1. **Runs but wrong**: free-form SQL "can produce correct-looking numbers that are subtly different across runs" [S33]; Genie "non-deterministic" [S8]; confine governed metrics to a semantic layer.
2. **Underspecified requirements, and a wrong verifier**: ambiguous data-model descriptions cause mismatches; rigid checkers and bad ground truth explain 82.7% of failed ELT-Bench tasks [S45].
3. **Incomplete pipelines**: 6 of 87 failed tasks referenced non-existent tables after "premature agent termination" [S45].
4. **Low end-to-end transformation success**: 3.9% of models (2025, stale) to 22.66% of tasks (Sonnet 4.5, 2026) [S46][S45]; extraction/loading largely solved (37% to 96%) [S45]; multi-tool workflow tasks 10.6-14.0% (2024, stale) [S47].
5. **Tool drift**: Kiro "often prefers" AWS CLI/bash over MCP tools (AWS calls this benign; for governance the agent can bypass the governed tool path) [S43].
6. **Environment/state errors**: deferral pointing at a model absent from prod; malformed diff patches (Wizard now handles both) [S27].
7. **Migration fidelity**: vendors still say to confirm migrated results match the original [S3].
8. **Coverage cliffs**: semantic layer answers only modeled questions [S33]; no Iceberg writes/DDL for the Google agent [S37]; no dbt unit tests on MVs [S34].

## 4. Transferable patterns, anti-patterns, failure modes
**Patterns to adopt**
1. **PR as the gate, with provenance**: the agent's PR states it was agent-made (dbt Wizard) [S27]; Kiro delivers PRs from sandboxes [S40].
2. **Plan/spec before action**: Kiro spec mode with acceptance criteria [S40]; Google plan review [S37]; Snowflake `/plan` [S17].
3. **System-owned, fail-closed policy outside the model**: Snowflake managed settings (restrictive fallback on a bad file) [S18].
4. **Verification ladder with Slim CI**: compile/parse, unit test, isolated build of only `state:modified+` with prod deferral, contracts/assertions, baseline data diff, downstream BI CI [S31][S34][S19][S39].
5. **Knowledge as skills and instruction files**: SKILL.md, GEMINI.MD, AGENTS.md; workspace-level skills enforce standards [S7][S37][S43].
6. **Evaluation sets for data agents**: ground-truth questions, per-step (GPA) metrics, LLM judges, feedback triage [S21][S8].
7. **Isolated code sandboxes** for agent-run code (Databricks Sandbox, Snowflake code-execution sandbox, Kiro sandbox) [S10][S21][S40].
8. **Environment self-checks**: Wizard detects broken deferral and skips no-op validation [S27].

**Anti-patterns (observed)**
- Default auto-approve by an LLM classifier; vendor says it is not a security boundary [S4].
- Unattended runs under a human identity [S5].
- "No intermediate approvals" without sandbox plus PR gate (Kiro is safe only because both exist) [S40].
- Trusting benchmarks or validators unaudited (ELT-Bench) [S45].
- Free-form text-to-SQL for governed metrics [S33].
- Letting the agent pick between governed MCP tools and raw CLI/bash [S43].
- Coupling the design to product names that changed within a year (finding 8).

### Independent evidence on AI-generated pipelines (checkpoint 6)
- **ELT-Bench (arXiv 2504.04808, v1 2025-04-07; STALE, >12 months)**: 100 end-to-end ELT pipelines (835 source tables, 203 data models); best agent (Spider-Agent + Claude 3.7 Sonnet thinking) correctly generated only **3.9%** of data models at ~$4.30 and 89.3 steps per pipeline.
