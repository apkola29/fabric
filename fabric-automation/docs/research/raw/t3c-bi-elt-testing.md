# T3c — BI, semantic-layer, ELT and data-testing/observability vendors (Fabric Code Factory)

Research date: 2026-10-30 · Thread: T3c · About 45 distinct sources read (target was ~30; see Gaps) · Report complete. Sections 1-6 are the report; Section 7 lists sources; Appendix A is the raw evidence log (not part of the word budget).

Legend: **Verdict** = Adopt / Borrow idea / Ignore. "UNVERIFIED" = could not confirm in a source. "[vendor claim]" = marketing claim, not independently verified.

## 1. Executive findings (≤10 bullets)

- **Do not buy an "AI data engineer" platform; assemble deterministic gates and borrow vendor patterns.** The category is churning and none of it is Fabric-native: Ascend is "winding down operations"; GX Cloud went to FICO and GX Core to Fivetran stewardship (May 2026); Fivetran closed its dbt Labs merger (2026-06-01) and donated SQLMesh to the Linux Foundation (Mar 2026); Datafold CI is "Classic"-only and its OSS data-diff is archived; Prophecy and Mage pivoted to business-user automation.
- **Every credible vendor gates agent changes the same way: branch/isolated environment, deterministic validation, human merge.** Omni (Branch Mode; Sandbox/Review/Auto apply modes; only Modelers and Connection Admins can merge), ThoughtSpot (Git branch = Org "environment", validate-merge API, GUID mapping), Cube ("humans review the change before it lands"), Matillion Maia (agent-task REST API with pending decisions and per-task tool permissions), Coalesce ("lands in Coalesce Desktop for review before it ships"). No vendor documents unattended production merges for BI artifacts. This validates the factory's branch → validate → human-approves-PR design.
- **Instructions are not enforcement.** Maia's docs say skills are guidance the agent "may" use, "not hard-coded rules"; Microsoft says the data agent "interprets but doesn't guarantee following" complex instructions. Enforcement must be gates outside the model.
- **A headless Fabric gate toolbox already exists:** Tabular Editor 2 CLI (BPA, schema check, deploy, CI annotations; no TE3 licence), Semantic Link Labs 0.18.0 (BPA, VertiPaq, impersonated-DAX RLS tests, broken-visual finder), Fab Inspector (JSON rules over PBIR and published workspaces plus DAX/T-SQL assertions; community-run), fabric-cicd 1.4.0, datacontract-cli 1.2.9 + ODCS 3.2.0 (documented Fabric support, `breaking` check, GitHub Action), Soda v4 (Fabric source, reconciliation; Elastic License 2.0).
- **The real gap is diff/regression harnesses.** No maintained turnkey data diff for Fabric was found (Datafold CI is Classic-only; reladiff stale since Aug 2025; SQLMesh's Fabric adapter is community-supported and `table_diff` on it is unverified). The only semantic-model regression tool found is Tabular Editor's `te test` (Limited Public Preview; docs give two expiry dates, 2026-10-31 and 2026-12-31); no report visual-regression tool was found. The factory should own a thin harness (inference): golden-DAX snapshots, EXCEPT-style diffs on zero-copy clones, `exportToFile` PNG diffs.
- **Gold-result comparison first, LLM judge second.** AtScale Canary (not yet GA) and Sigma's eval guide both score numeric answers against known-correct results; Fabric's data-agent SDK evaluation (preview, 0.1.33a0) defaults to an LLM "critic" prompt. Risk: Microsoft states service principals are supported for data agents "only as part of ALM scenarios", so a headless SPN-run eval gate is unverified.
- **AI-generated BI artifacts fail in well-documented ways.** Microsoft lists duplicate/overlapping measures, implicit measures, ambiguous date fields, hidden fields, non-descriptive names; ThoughtSpot: "a Model that imports cleanly can still answer badly"; Omni: direct model edits can change existing results unnoticed. Enterprise text-to-SQL was hard: an o1-preview-based agent solved 21.3% of Spider 2.0 tasks (Nov 2024; stale) versus ~96.7% best self-reported on the live leaderboard today (setting unverified) with heavy scaffolding.
- **Non-prod pattern: virtual or zero-copy, not copied.** SQLMesh virtual environments (+ date-windowed dev), Fabric Warehouse zero-copy table clone (inherits RLS/DDM; Warehouse only), ThoughtSpot GUID mapping, ODCS 3.2 variables ("no secrets in Git").
- **Post-deploy observability agents are phase 2, not a merge gate.** Monte Carlo "Bayes" (Fabric connector in public preview), Soda RCA/MCP, Elementary, Coalesce Scout. Borrow their graduated autonomy ladder (manual → assisted → supervised → autonomous).
- **Preview/pre-release dependency risk is high:** te CLI, data-agent SDK, Soda Contract Autopilot (preview), AtScale Canary/CoModel (coming), dbt Wizard (beta). Keep each behind an adapter; require a deterministic fallback.

### (b) How mature vendors handle test data and non-production environments

- **Virtual/shallow, not physical copies.** SQLMesh dev environments are schema-suffixed views over fingerprinted snapshots; only changed models recompute; a dev environment has a start/end date window (primary docs). Fabric Warehouse zero-copy table clones (current or point-in-time, 30-day default retention) inherit RLS/DDM and are pitched "for development and testing in lower environments"; the clone page covers Warehouse only.
- **Environment = branch/stage paired with a target, with ID mapping.** ThoughtSpot pairs a Git branch with an Org and remaps GUIDs on deploy; Omni branches carry the model and impacted documents together; Sigma uses read-only version tags; Fabric data agents promote through deployment pipelines (one workspace per stage).
- **Staging built from the PR branch.** Datafold CI needed a CI step that builds a staging schema from PR code, then diffs it against production.
- **Fixtures for logic tests.** SQLMesh YAML unit tests give per-model inputs and expected outputs; AtScale Canary cases bundle question, test data, gold SQL and validated result.
- **Config without secrets.** ODCS 3.2 variables let one contract serve dev/test/prod "with no secrets in Git".
- **Gap:** no source found on masked or synthetic data generation for Fabric BI (UNVERIFIED; T4/T5 may cover).

## 4. Transferable patterns, anti-patterns and observed failure modes

**Patterns to borrow (each seen in at least one primary vendor source):**
1. **Autonomy dial per change type** (Omni Sandbox/Review/Auto; Monte Carlo Manual→Autonomous, "earns more scope as it proves reliability"): default every Fabric artifact class to Sandbox/Review, promote classes to Auto only on measured pass rates.
2. **Agent-task API with pending decisions and per-task tool allow-list** (Maia): model intake → task → "awaiting decision" → approve/answer; revoke tools by replacing the permission list.
3. **Branch ↔ isolated environment ↔ ID mapping** (ThoughtSpot GUID mapping; Fabric deployment pipelines; fabric-cicd).
4. **Gold-suite promotion gate; failed cases become permanent regressions** (AtScale Canary; Sigma eval suite) and re-run whenever model *or* agent LLM changes.
5. **Constrain the generator to a validated semantic surface** (Cube Semantic SQL; Fabric AI data schema) so unknown identifiers are rejected before execution.
6. **Expose the gates to the agent as tools** (Datafold diff/monitors via MCP "so your coding agents can validate their own work"; Soda MCP; Coalesce Catalog MCP; Elementary MCP) so the factory's inner loop self-corrects before a human sees the PR.
7. **Context as versioned artifacts** (Omni model injected as agent context; Fivetran "Agents Schema"; ODCS 3.2 "context for AI systems"; Hex Context Studio).
8. **Evidence bundle in the PR** (data diff summary + test results + screenshots), as Datafold's PR comment and TE/Fab Inspector CI annotations do.

**Anti-patterns / failure modes actually observed:**
- Treating **AI code review as a correctness gate**: Datafold's AI review is an org-defined SQL style rule set (max 20 comments, once per PR).
- **Rules in skills only** (Maia: skills are guidance).
- **LLM-judge-only evaluation** (AtScale: "a second model gives you another guess" [vendor stance]; Sigma separates deterministic factual checks from judged reasoning quality).
- **Production-critical dependence on preview/alpha or "coming" features** (te CLI, data-agent SDK, Contract Autopilot, Canary, dbt Wizard).
- **Dependence on a consolidating vendor roadmap** (Ascend shutdown; GX Cloud sale; Datafold Classic/new split).
- **Single-maintainer community tools without fallback** (Fab Inspector, 94 stars; reladiff stale since 2025-08).
- **Shared-model direct edits without a branch** (Omni docs: unnoticed changes to existing queries).
