## Shared preamble (read first, then your slice)

You are doing a THIRD LOOK at ONE piece of an open-source project: the INSTRUCTION LAYER of a "Fabric Code Factory" (design and toolchain in the public repository https://github.com/apkola29/fabric, folder `fabric-automation`). The factory turns a natural-language requirement for Microsoft Fabric and Power BI items into a verified draft pull request. People and unattended jobs run AI agents (Claude, GPT, Gemini and Grok models, under Copilot CLI, VS Code, Claude Code or Gemini CLI). The toolchain kit pins the agent skills and MCP servers that those agents may load. The instruction layer is the text that tells an agent what it has, where its knowledge comes from, how sign-in works, what to do when a server does not answer, and how to look for newer skills and servers.

THE HISTORY. A first review (three families, three slices) raised 25 findings: A-1 to A-6, B-1 to B-12 and C-1 to C-7. The author fixed them. DESIGN RULES THAT BIND (`docs/04-design.md`, section 2): HR-3 (an agent job holds no credentials; a credentialed or hosted MCP server may be used only by a person in `dev` mode or by the trusted executor), HR-9 (nothing is installed or updated at run time; everything is pinned), HR-12 (a changed tool contract is a stop). So R5 is implemented as REPORT, not ADOPT (design 3.13: "Never auto-update"): a run reports what is newer and keeps working on the pinned set, and a person adopts a newer version in a reviewed pull request. The owner can change that decision. R3 is true for a person's session (they sign in with `az login` or a browser); an unattended job has no network and no credentials in the agent plane, and the identity of an unattended executor is an open spike (S2, S6).
